# 阶段 A：聊天式预问诊与模拟预约实施记录（2026-09-27）

## 产品边界

- 目前没有合作医院；医生、排班、号源、预约单均为**模拟数据**，不产生真实挂号或就诊凭证。
- 本阶段仅支持成年、本人、非孕产期用户的辅助预问诊；急症触发前置安全提示，不给普通预约建议。
- 症状时间线保存患者自述原文，不是电子病历；AI 输出只供就医方向参考。

## 已完成

1. 患者会话、消息、分诊评估版本、资格确认和症状时间线保存到数据库；接口按 JWT 患者身份隔离。
2. 首轮非紧急描述先追问，后续消息在同一会话继续分析；可查看历史会话与多个评估版本。多科室线索优先指向全科/人工导诊。
3. 模拟号源和预约保存到数据库，预约事务内条件扣减余量；同一患者与幂等键重复请求返回同一预约。前端提交期间禁用重复点击。
4. 后端分出 `TriageEngine` 和 `DoctorDirectory` 边界：会话编排与预约服务不再直接依赖演示数据类。管理概览由持久化会话和预约计算，旧内存预约接口及绕开会话存储的旧分诊写接口已移除。
5. 分诊结果中的医生使用最新模拟号源余量，约满不再继续推荐该号源。分析异常时会话标为“待重试”；前端失败后读取会话，避免把已保存的症状重新放回输入框。
6. 默认开发库为持久化 H2，提供 MySQL profile；支持未配置密钥的演示模式，以及通过进程环境变量启用 OpenAI 兼容模型。

## 本轮验证

- JDK 17：后端 `mvn test` 通过；`mvn package -DskipTests` 通过（已固定与本机 Maven 3.6.1 兼容的 jar 插件版本）。
- 前端 `npm run build` 通过，包含 TypeScript 检查。
- `AI_HOSPITAL_LIVE=1` 的前端认证测试经 `5188` 代理全部 4 项通过，包括旧令牌自动刷新。
- 经 `http://127.0.0.1:5188/api` 实际登录患者后，请求模拟号源，预约一次并用相同幂等键重试：返回相同预约号；骨科号源从 20 降为 19；本人预约列表有 1 条。管理员概览同步显示 1 条预约、2 条持久化会话。
- 重启后再次通过 `5188` 代理验证：预约仍有 1 条、骨科余量仍为 19、后台预约数为 1；旧 `/messages` 写入接口已返回 404，不能绕过新会话流程。
- 新建李四的腹部症状会话，首轮返回追问，第二轮返回消化内科、4 条有序消息、2 条知识依据；运行态结果为 `LIVE / qwen3.7-flash-2026-07-15`。该操作在本地演示库留下 1 条测试会话。
- 自动化测试覆盖会话多轮、版本、患者隔离、急症、资格限制，以及预约保存、单次扣号、幂等重试、患者记录隔离和并发抢最后一个号源。
- 本轮未做浏览器逐按钮端到端验收：内置浏览器连接组件版本不匹配，无法完成页面点击验证；改以实际 HTTP 代理请求和前端构建验证。也没有在本机 MySQL、Qdrant 或真实医院接口上验收。一次真实 Qwen 回归成功不等于所有 AI 症状场景已验收。

## 分层现状与待完成

- `api` 控制器处理 HTTP/JWT；`service` 中 `TriageConversationService`、`SimulationBookingService`、`AdminOverviewService` 编排用例；`domain` 定义替换边界；`HospitalDemoService` 仍承担演示分诊、知识与工具数据。当前是**部分分层**，并非生产架构完成。
- 下一步应拆分患者/管理控制器，抽出 Repository、事务边界和医院适配器；接入真实医院前，必须有医院授权、排班同步、预约确认/取消回执与审计。
- 管理端知识资料、MCP 工具配置和调用日志仍是演示/内存实现；检索不是完整的 Qdrant 向量 RAG，工具轨迹部分为模拟结果。不能把它们标称为已上线的真实 Agent 编排。
- 登录账号和任意非空密码仅用于演示。上线前必须接入真实身份认证、密钥管理、访问审计、数据加密与隐私治理。
- 当前预问诊请求同步等待模型，尚未完成真正的流式 token 输出和后台任务恢复；高并发、多实例会话并发控制、消息级幂等与预约取消仍需补齐。

## 同日补充：多科室医生与历史结果展示

- 原因：原结果结构只给主方向保存一个医生；前端只显示一张当前选中的卡片，导致用户误以为旧版结果被删除。实际上版本数据一直保存在数据库中。
- 修复：每个相关科室方向保存一名当前可用的模拟医生；多科室时仍把全科/人工导诊放在主方向，其他科室以并列候选显示。最新版本可预约候选医生；紧急提示依旧禁止普通号源预约。
- 当时曾尝试在消息流中逐版展开完整卡片；这不符合用户希望的“单张卡片＋版本按钮切换”交互，已在下节调整。
- 自动化后端测试覆盖两个科室医生、候选医生预约及两版结果持久保存；前端 `npm run build` 通过。
- 通过 `5188` 实际请求建立一条“头晕 + 上腹痛反酸”测试会话：保存 2 版、6 条消息；第一版同时含神经内科李敏与消化内科张伟，生成第二版后第一版摘要未变化。第一版模型超时，标为 `FALLBACK`；第二版成功调用模型，标为 `LIVE`。因此模型响应时长仍是待解决问题。
- 浏览器控制技能仍因本机插件组件版本不匹配无法连接，未宣称本轮完成逐按钮视觉验收。

## 同日调整：按需追问、三类症状与版本切换

- 首轮不再固定追问。能识别就医方向时立即生成带免责声明的初步分诊；完全缺少可用症状线索时才先要求补充。后续消息继续生成同一会话的新版本。
- UI 恢复为一张完整结果卡片，上方的“第 1 版／第 2 版”按钮切换显示已持久化的历史结果。旧版摘要、推荐、知识依据和工具轨迹不被新版本覆盖；历史版本不提供直接预约按钮。
- 扩展“疑似骨折／摔断 → 骨科”、“嗓子疼／咽痛 → 呼吸内科”、“痛经／经期疼痛 → 妇科”的演示分流，并为妇科增加模拟医生。多个症状可同时返回多个科室及对应医生；多科室主方向仍提示全科／人工导诊。
- 增加外露骨头、持续大量出血和无法吞咽等安全规则；疑似骨折提示尽快线下评估，不以模拟预约替代及时就医。新增 3 份根据 NHS 官方公开页面整理的知识资料。
- JDK 17 的 `mvn test`、前端 `npm run build` 通过。经 `5188` 实际请求：“我手摔断了，嗓子疼，还痛经”首轮直接生成第 1 版，同时返回呼吸内科陈静、骨科刘强、妇科赵琳；续问后有 2 版，第 1 版摘要保持原样。两次模型调用分别是 `LIVE` 和超时 `FALLBACK`。
- 内置浏览器控制技能仍因版本不匹配无法连接；版本按钮的页面点击没有完成自动化视觉验收，不能把构建通过等同于逐按钮验收。
