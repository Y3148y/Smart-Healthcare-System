# 鼻部症状明确挂号后仍无限追问（2026-10-01）

## 现象与原因

合成复现路径：流鼻涕、鼻塞等鼻部症状经过多轮交流，患者明确表示“我要挂号”后，系统继续追问就诊日期而不生成分诊版本。原会话状态为“待补充信息”，无分诊结果；当时本地知识检索已命中两个片段，演示号源亦有余量，所以不是知识或号源缺失。

根因是 `RuleBasedTriageEngine.needsClarification()` 在检查挂号意图前就因候选科室为空返回；鼻部症状尚未列入专科规则候选。LLM 只能生成引导文字，不能越过该后端门槛创建预约，因此出现“承诺进一步安排、实际反复追问”的体验问题。

## 本次修复

- 仅在检测到肯定的鼻部症状且患者明确提出挂号意图时，允许受控回退到**全科医学科**；单纯咨询仍保持多轮引导，不能将任意未知症状强行映射到全科。
- 原有急症规则、RAG 有依据门槛、医生可用号源及预约幂等/扣号校验保持不变；无知识依据时仍不生成普通预约。
- 引导型 LLM 提示词不再允许承诺“回答就诊日期后自动生成或完成预约”，实际预约需患者在页面操作。
- 当前仍为模拟医院科室和号源，未接入真实 HIS；全科入口不表示已经判明病因，也不是正式医疗分诊结论。

## 验证

JDK 17、无 `AI_*` 环境变量的 `backend/mvn test`：46 项通过、0 失败；`frontend/npm run build`：通过。新增集成测试覆盖“多轮鼻部症状 → 明确挂号 → 有依据的全科推荐 → 模拟预约成功”，以及无症状或否认鼻部症状时不生成推荐。临床评估与独立复核仍待完成。

重启 8080 后通过 5188 前端代理做真实模型冒烟：演示账号 `lisi` 的合成输入“鼻塞从昨晚开始，流鼻涕，我要挂号”生成 1 版分诊，状态“已完成分诊”，全科医学科、周宁医生（测试时剩余 20 个演示号源）、2 个知识片段、`grounded=true`、`modelStatus=LIVE`。测试会话 ID 为 `2f997243-2164-4fa7-9a7f-f657ca441848`；未实际扣减号源。旧会话不会被自动改写，需患者再次发起挂号意图才会触发新规则。
