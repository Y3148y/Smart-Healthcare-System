# 项目入门：从启动到读懂一轮问答

本指南面向首次接触本仓库的Java开发者。先完成离线测试，再运行隔离演示，最后才接入真实模型；无需先理解所有AI术语。完整启动命令以[README](../README.md#快速开始)为准。

## 1. 先知道这个项目是什么

这是一个可运行的医疗导诊开源示例，包含患者页面、管理员后台、知识工具和评估工具，不是医院诊疗系统。

| 能做 | 不要误认为 |
| --- | --- |
| 根据症状咨询检索资料，展示有来源的医学原文 | 已经诊断疾病、证明建议适用于该患者 |
| 模型选择允许的查询工具 | 模型可以任意执行代码或创建预约 |
| 查询科室、医生与模拟排班，患者确认后模拟预约 | 已连接医院HIS或真实号源 |
| 保存本人资料、会话与来源绑定的AI观察 | 正式病历、电子健康档案或医生工作台 |
| 管理员导入、审批和发布知识 | 操作者点击审批就完成临床审核 |

示例认证只供本机演示，不能暴露公网。不要录入真实患者数据或将密钥写入仓库。

## 2. 用最少术语理解架构

- **LLM**：外部模型，负责结构化抽取、选择只读工具、选择资料与核对选材；不是所有回复都调用它。
- **Workflow**：Java控制的流程，负责安全优先级、授权、数据保存与预约约束。
- **Agent**：普通咨询中的有界模型工具循环，最多3次规划、4次只读工具执行；不是多Agent会诊。
- **RAG**：先检索获准知识，再用实际资料约束回答。当前医学正文采用原文，不让模型自由改写。
- **BM25 / embedding**：分别提供词法与向量候选；相关度分数不是医学可信概率。
- **RRF / rerank**：前者按排名融合候选，后者可选地重新排序；默认关闭rerank。
- **trace**：串起同一轮意图、工具、检索、生成、核对记录的关联标识，不是思考链。
- **MCP**：工具访问协议。仓库另有管理员工具服务，患者Agent不通过MCP客户端执行工具。

## 3. 第一站：不调用外部模型的测试

准备JDK17和Node.js20+。在没有日常 `AI_*` 环境覆盖的新终端执行：

```powershell
cd backend
.\mvnw.cmd test
cd ../frontend
npm ci
npm test
npm run build
```

Windows先将 `JAVA_HOME` 指向自己安装的JDK17；Linux/macOS使用 `./mvnw`。Maven Wrapper首次需要下载Maven及依赖，不要求全局安装Maven。

默认测试使用模型桩与测试库；测试通过不表示真实模型、MySQL、ES、Qdrant或浏览器链路已通过。显式外部组见[测试矩阵](../CONTRIBUTING.md#测试入口)。

| ES / Qdrant / MySQL | 本机9201 / 6333 / 3306 |

## 5. 第三站：验证真实模型，不靠URL猜

在后端运行环境中配置聊天base URL、模型ID、密钥及embedding服务。默认真实模式要求必要配置，缺失会启动报错；demo入口URL与LLM模式是两回事。

1. 从管理员运行信息确认配置状态；配置存在不等于远端额度可用。
2. 在隔离会话发一条一般咨询，如“偏头疼两天，想了解一般注意事项，暂时不挂号”。这只是合成测试，不是医学期望标签。
3. 展开本轮说明，分别观察意图、实际工具、检索、采用来源和模型终态。
4. 在管理员观测按trace关联调用。`Agent执行/COMPLETED`才说明工具循环完成，最终有回答不代表Agent一定完成。
5. 检查生成与核对是否实际取得供应商用量；未知不能记为0，本地工具的0也不是模型免费。

真实调用会消耗额度。不要反复提交相同问题直到得到好结果；保留失败样例和实际配置。

## 6. 跟读一轮业务

```text
患者消息
→ 本人权限/请求幂等/轮次登记
→ 原话安全检查（急症直接走固定流程）
→ 普通咨询意图抽取与来源校验
→ Agent在收窄后的白名单里选只读工具
→ BM25/Qdrant候选与融合、可选重排
→ 模型选择来源ID与受控对话项
→ 后端组装原文、检查选材与来源新鲜度
→ 保存消息/来源/状态/调用记录
→ SSE发送核对后的正文分段
```

预约是另一受控分支：查询不等于挂号，准备不占号；患者确认后重新验证状态并事务扣号。Agent没有预约写工具。

## 7. 按顺序阅读代码

所有路径相对仓库根目录；类型可用IDE搜索定位。

| 顺序 | 类型 | 阅读时回答的问题 |
| --- | --- | --- |
| 1 | `TriageConversationService` | 谁校验本人、登记轮次、保存结果？ |
| 2 | `TriageWorkflow` / `WorkflowRouter` | 安全、追问、普通咨询如何分流？ |
| 3 | `LangChainIntentExtractor` / `IntentValidator` | Schema与患者原话绑定如何验证？ |
| 4 | `AgentRunner` / `AgentToolGateway` | 工具如何收窄、去重、限时、阻止越权？ |
| 5 | `HybridKnowledgeCatalog` | 候选与最终片段有什么区别？ |
| 6 | `MarkdownChunker` / `QdrantSemanticIndex` | 片段位置、版本、哈希如何进入索引？ |
| 7 | `SourceAnswerPlan` / `AnswerSupportReviewer` | 为什么引用合法不等于适用条件正确？ |
| 8 | `AnswerEvidenceFreshness` | 审批撤回或资料变化后是否还能展示？ |
| 9 | `PendingBookingService` / `SimulationBookingService` | 确认、幂等和扣号怎么配合？ |

不需要第一天读完所有测试。先选一个模块，读它的生产入口、一个正例和一个失败例，再回到[架构](ARCHITECTURE.md)核对理解。

## 8. 知识资料不是URL书签

资料位于 `knowledge/corpus/<主题>/<症状>/`，含中文正文、provenance与必要来源快照。正文元数据通过哈希关联来源，线上从数据库的获准资料检索，不在每次问答时抓来源网页。

切分按标题和段落，同章节短段合并；长段上限420 Unicode码点、重叠60。当前11篇78片段实际未触发长段重叠；配置上限不等于实际长度。完整段落也不保证跨段医学条件完整。

```powershell
# 仓库根目录，离线，不调用模型
node tools/knowledge-sync/validate-document.mjs --corpus
# backend编译后，用应用实际切分器核对
java --class-path backend/target/classes tools/knowledge-sync/ChunkInspection.java knowledge/corpus
```

## 9. 遇到问题先分层定位

| 现象 | 优先检查 | 不要直接得出 |
| --- | --- | --- |
| 页面拒绝连接 | 前端端口、进程与代理目标 | 模型没有额度 |
| 后端启动失败 | 最早的根异常、JDK、数据库/必填配置 | Spring或模型能力不行 |
| 模型未回答 | 是否规则/服务路径、生成/核对失败码、超时与配置 | 必然是额度用完 |
| 有候选但未采用 | 各阶段阈值、身份/条件过滤、最终引用 | 从未执行RAG |
| 没有推荐医生 | 风险、依据、科室启用、医生/排班/余号 | 一定是资料不足 |
| Maven CI失败 | Wrapper下载、编译、测试哪个阶段 | 有BUILD FAILURE就一定业务测试错 |

例如历史CI曾在下载Maven发行包时失败，后端测试并未开始；不能通过改业务代码“修复”下载错误。也不能以本机绿代替远端CI绿。
