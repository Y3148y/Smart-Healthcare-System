## 架构与职责

离线：来源登记 → 原文快照 → 整理/审核 → 带来源的片段 → embedding → Qdrant。原文与审核版本需要后续持久化任务；本轮不冒充已经完成，当前上传审批依然是内存演示。

在线：用户描述 → query 构建 → BM25 与 dense 候选 → RRF → rerank → 证据集合 → LLM 带片段引用回答。安全规则先行，急症不等待检索/模型。科室与号源属于业务目录，不由 RAG 伪造。

检索接口使用独立候选深度（默认 20）与最终证据数（默认 3）。词法分、cosine、RRF、rerank 分不可混合成一个“可信概率”。证据通过筛选仍不证明生成的每句话有依据；逐句引用/支持性校验与临床审核是明确的后续上线门槛。

## 评测口径

检索评测报告 Recall@3、MRR、无答案查询误召回率、禁止资料出现率与耗时。查询集是工程相关性标注，不是临床敏感度。先锁定查询和预期，再改排序；保留失败条目，不为全绿删除难例。真实 dense 与 rerank 未调用时明确写未测，不用测试桩分数代替。

## 真实业务仍需补齐

审核状态落库、文档撤回/过期、租户与医院隔离、重建切换/回滚、原文到摘要可追溯、临床专家标注集、回答级证据一致性、服务 SLA/监控与数据合规均不能仅凭本轮检索改造宣称完成。

## 2026-10-03 实测与限制

- 模型：embedding `qwen3.7-text-embedding`，rerank `gte-rerank-v2`；Qdrant 本地 6333，集合 `ai_hospital_knowledge_v2`，1024 维，12 个片段、11 份整理资料。不是在线搜索，每次查询只请求远端向量/重排计算，原文片段来自本地批准语料。
- 开发集先暴露 0.5 误拦：如“我胸口痛”的胸痛文档已是 dense 第一名（0.6483），却因 rerank 0.2835 被淘汰。基于开发集选择 0.15 后，再测预先写定的额外 12 条保留集。没有按症状改词表或专门调分。
- 默认配置仍为 0.5；`rag-live` 暂用 0.15，均可由 `AI_RERANK_MIN_SCORE` 覆盖。这个阈值只是在当前模型和小语料上的工程参数，更换模型/语料必须重新评测。分数不是可跨问题比较的医学概率。
- 开发集第二次实测冷查询 3405ms，余下 11 条 311–572ms；不含 LLM 生成耗时，不是并发压测或 SLA。
- **仍未解决**：保留集“感觉天旋地转而且恶心”除了正确第一名，还返回消化和胸痛资料；开发集胸痛查询会夹带鼻部资料中的胸痛警告片段。禁止资料指标只检查预先列出的禁止标题，不是完整 Precision@3，也不证明其余片段都合适。下一步应扩充分片级标注与证据支持校验，不能继续靠降阈值宣称解决。
- 规则急症路径在新代码中绕过 RAG，因此不再把无关召回资料冒充紧急规则出处；已有历史结果不改写。通用检索仍应继续处理上述精度缺口。
- 旧 InMemoryKnowledgeCatalog 的固定词法检索只留作历史基线/兼容测试，默认 @Primary 在线路径已经使用 Bm25Retriever；后续可以单独清理兼容层，不能声称已删去所有旧实现。
- API：管理员 `GET /api/admin/knowledge/search/details?q=...` 输出每路排名/原分、融合分、重排分、去留原因；`runtime` 是最近完成检索的状态，不是实时健康探针。患者不显示原始相似度百分比。
