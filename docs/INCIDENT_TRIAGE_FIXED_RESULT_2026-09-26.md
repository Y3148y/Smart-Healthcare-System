# 智能预问诊固定返回呼吸内科：根因与修复

日期：2026-09-26

## 用户可见现象

患者输入“我最近头晕想吐”，页面仍显示“呼吸内科 / 陈静”和固定的呼吸科知识依据；助手没有针对问题回答。

## 确认的原因

1. 前端分诊请求失败时，`startTriage()` 无提示地调用 `demoResult()`，该函数始终生成呼吸内科、陈静和相同的知识卡片。这是截图中固定结果的直接原因。
2. 后端仅用“咳、痰、喘、胸闷”以及“胃、腹痛、反酸、恶心”两组关键词分科；未识别头晕、眩晕等症状。
3. 原模型调用只用于润色预先选定的科室说明，不负责针对患者原话作答；异常被静默吞掉。
4. 同一模型的短请求直连成功，真实预问诊提示词需约 25–27 秒，而后端先前设置 20 秒超时，因此走了规则降级。模型 ID 和密钥可用。

## 修复

- 删除前端固定呼吸内科结果。接口失败时显示“分诊失败”，不伪造医生、知识依据或 Agent 轨迹。
- 增加头晕、眩晕、头痛等症状的神经内科初诊分流，补充神经内科和全科演示号源。
- 加入北京协和医院头晕资料与国家卫健委卒中警示资料，保留官方 URL 作为 RAG 来源。
- LLM 提示词改为直接回应患者原话、说明信息不足并提出关键追问；危险症状仍由服务端规则优先处理。
- 模型请求限制生成长度，超时调整为 35 秒；结构化结果返回 `modelStatus` 和 `modelName`，页面明确显示真实模型回答或降级状态。
- 无模型或模型失败时，规则回答也按症状给出相关追问，不再固定为呼吸内科。

## 实测证据

- 后端 `mvn test` 通过，新增“头晕想吐不返回呼吸内科”回归用例。
- 前端 `npm run build` 通过。
- 通过正在运行的 `5188` 前端代理调用：输入“我最近头晕想吐”，返回神经内科、李敏、北京协和医院头晕资料。
- 最终在线请求返回 `modelStatus=LIVE`、`modelName=qwen3.7-flash-2026-07-15`；模型针对起病方式、持续时间、体位变化及危险信号作答，耗时约 25 秒。

## 当前实现边界

分诊的风险阻断和科室选择仍由服务端规则控制；LLM 负责自然语言回答与追问。当前页面每次发送会创建新会话，尚未实现带历史上下文的多轮对话。该界限应在后续实现中继续清晰标记。
