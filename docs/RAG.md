# RAG 设计与验证

## 能力与边界

仅当显式 `ai.rerank.enabled=false` 且向量查询成功时，最终K个片段先保留向量路线前 `ceil(K/2)` 项，其余从RRF顺序补足、去重；开启重排时不使用此策略。强制语义模式仍要求全部最终片段经原向量阈值确认，故障仍按原闸门阻断。诊断原因 `selected_semantic_reserve_without_rerank` 表示路线保留，不表示医学内容已核实。该临时无重排策略需用固定片段标签和真实回答复验，不沿用重排版质量成绩。

管理员检索诊断的 `lexicalTerms` 区分 `titleTermFrequency` 与 `bodyTermFrequency`，用于识别仅标题命中而正文无对应词的候选。两字段不改变BM25计分或RRF排序，也不证明医学相关性；片段质量仍须按完整冻结语料标注并评估。

患者流程由Java工作流显式调用检索和业务工具，模型不自主选择工具。RAG使用已审批的本地数据库正文，不在回答时访问来源URL，也不通过搜索网页临时补全文。
本系统未经临床审核，知识命中与相关度分数都不能证明诊断、风险排除或个人适用性。临床审核、真实HIS接入及完整医学质量验收未完成。

## 资料与持久化

本地编辑资料采用最小Markdown头+正文，完整采集与审核信息在同目录provenance.json，并通过哈希绑定；读取器核验全部来源快照后，仅发送医学正文和既有接口metadata进入待审。本机2026-10-07新增11个NLM健康主题摘要作为旧NHS资料的补充，抽取限于政府编写的topic-summary，不混入受限百科和第三方外链。资料与审核记录不公开提交。章节到来源的映射目前保存在本地，未声称检索片段已具备在线逐句出处。

应用不再携带旧11篇短医学摘要；历史正文只作为test/resources工程回归夹具，不进入应用包。全新数据库需要显式导入与审批，不自动附带开发者本机语料。
已有数据库按持久化正文和审批状态恢复，不被启动资源覆盖。MyBatis保存正文、来源元数据及当前审批状态，BM25和片段缓存仍在进程内。
空数据库是合法启动状态：空持久化快照清空检索缓存，不恢复历史夹具；缺失（null）快照仍拒绝恢复。没有已审批资料时不能生成资料支持的回答。
开发者本机源网页快照、英文抽取、中文整理稿及采集哈希保存在忽略目录，不提交第三方全文、患者正文或运行报告。
操作者审核不等于专业临床审核，中文整理稿也不等于完整原文翻译。

本机新整理稿已按用户明确授权通过管理员接口发布，并撤回旧版保留历史；这是本机数据库操作，不是公开仓库的自动初始化。临床审核仍未完成。原始待审编辑稿与运行库审批状态分开记录，不能从本地MD头推断在线状态。

## 离线流程

登记来源与许可 → 抓取本地快照 → 核对哈希 → 正文抽取与清洗 → 核对适用条件与中文稿 → 结构化待审入库 → 另行审批 → 片段及向量同步 → 固定评估。
来源工具遵守抓取限制，失败不伪造正文、许可或日期；提取表格等告警需要人工复核。资料介绍页不能冒充完整教材。
管理员提交title、body和metadata。元数据包括来源机构/链接、实际采集时间/哈希、语言、内容类型、主题、适用人群、排除条件、前提及证据用途。
许可pending/restricted不能审批发布；permitted必须有依据，但仍只是操作者声明，不是法律或临床认证。旧资料缺字段标为LEGACY_UNKNOWN。

### 可复现待审入库

管理员录入页支持同时选择同一目录的 `document.zh-CN.md`、`provenance.json` 和全部 `source*.en.md`。浏览器核验待审状态、审计文件哈希、来源快照哈希及多来源关联，剥离文档头后仅将医学正文和接口支持的来源/适用元数据提交到既有待审接口。带文档头的MD不能作为普通正文上传。文件读取不调用网络；提交使用当前管理端认证，不依赖开发终端令牌。导入时许可恢复为待核对，用户另行核对用途与许可，不自动审批或替换在线稿；本地章节来源与完整审计扩展字段仍未持久化。

在tools/knowledge-sync运行 `node import-local.mjs packet.json`，默认只校验；显式加`--apply`才向本机后台创建PENDING_REVIEW资料。
资料包包含schemaVersion=1、title、body、contentSha256（UTF-8正文SHA-256）及上述metadata。校验哈希不证明医学正确性或来源授权。
后台凭据仅通过KNOWLEDGE_ADMIN_TOKEN进程变量注入，KNOWLEDGE_IMPORT_BASE_URL默认http://127.0.0.1:8081/api/，禁止外部地址和重定向。
该命令不登录、不抓取网页、不审批、不替换现有正文、不触发自动发布。重复导入可能创建重复待审记录；当前没有服务端导入幂等键，超时后须先核对后台再重试。
原始快照、已发布正文及许可仍需按实际情况准备，工具不会补造；完整私有资料包的版本化发布交付仍未完成。

## 切分与索引

MarkdownChunker按标题章节和段落切分，同章节短段按原顺序打包，不跨标题。长段最多420个Unicode码点、重叠60码点，优先在合适句末切开。
每个片段保存文档ID/内容版本、稳定片段ID、章节路径、原始位置、正文哈希和切分策略。长医学条件可能跨窗口，仍需片段级审核，不能仅凭切分成功认定语义完整。
BM25统计索引与embedding/Qdrant使用同一批准片段；Qdrant payload包含溯源和模型名，校验请求快照中的point身份及payload，不证明医学相关性。
新collection可配置HNSW参数；小数据可能全扫描。向量已存储不等于HNSW已经参与查询，已有collection也不会因修改默认配置自动更新。离线清单读取Qdrant实际`indexed_vectors_count`；字段缺失记为-1（未知），不能把未知伪装成0。2026-10-07本机观察到collection为12 points、0 indexed vectors、1024维Cosine、m=16、ef_construct=100、full_scan_threshold=10000KB；这与小collection走精确扫描相符，不证明线上其他实例配置相同。
KnowledgeIndexBuildRunner显式启用离线构建，复用批准语料同步入口，生成本地片段/模型/实际collection配置清单；数量或身份不一致时拒绝成功。清单不包含患者query和资料正文。

## 在线检索

本轮问题与有界上下文 → BM25及百炼embedding/Qdrant多路候选 → 单一RRF融合 → 百炼rerank → 按资料去重（每份资料最多保留一个片段）→ 有界片段 → 生成及回答核对。
阈值、候选深度和依赖要求由配置控制。rag-live要求语义检索与rerank可用；其他配置可提供标识明确的本地降级，故障不能伪装成无医学资料。
免费重排额度耗尽时，可显式临时设置 `ai.rerank.enabled=false` 与 `ai.retrieval.require-rerank=false`。这会完全跳过重排请求，按现有RRF顺序选留，标记 `DISABLED_BY_CONFIGURATION` / `UNRERANKED`；不修改rag-live的默认严格要求。仍保留语义依赖闸门、引用校验及回答核对。未重排结果的质量须单独评估，不能沿用重排版通过率；评估器现有严格依赖通过指标不会把此模式算为完整通过。
诊断保留各路排名、BM25实际词项贡献、重排分数及选留理由；患者端不展示内部评分。评估报告保留候选片段、哈希和chunk版本引用；只保存在本机忽略目录。重排传输错误提供脱敏分类（超时、DNS、连接、TLS、HTTP状态、无效响应等），不记录异常原文、密钥或患者query。模型不调用工具也不负责修补召回。
同一词可出现在其他主题的警示条件里。例如感冒稿提到胸痛需评估，不意味着胸痛患者患感冒；标题不同不一定毫无关联，得分高也不代表可用于推断病因。
生成与回答核对共用适用性约束：病程、护理、病因和就医条件不能跨症状背景套用，伴随警示不能证明主要疾病。这是提示约束，不是确定性医学判断；合同测试只证明两处接入，实际模型遵守程度仍需生成评估。
生成JSON拒绝重复字段及同段重复引用；LIMITATION必须不带引用，不能把限制说明的资料计入实际采用。该结构校验不判断正文医学断言是否受支持，仍由独立模型核对并保留其不确定性。
安全闸门独立执行，急症不等待检索或模型，模型不得覆盖风险限制。检索命中与答案实际采用依据分别记录。

## 审批与撤回

数据库写入成功后才更新目录与索引缓存；写入失败不能只在内存显示成功。待审资料不进入批准片段集合。
撤回先持久化PENDING_REVIEW，再移出缓存；保留正文、来源及历史回答。Qdrant旧point可暂存，但后续请求的活动集合排除它，不要求向量服务可用才能撤回。
在途快照和历史回答不追溯取消。不可变审核版本、跨实例缓存通知、完整修改历史及自动留存策略尚未实现。

## 工程验证

后端普通JDK17 Maven测试不调用真实供应商；外部测试需显式启用。测试夹具验证机械行为，不等于医学质量或线上成功。
tools/knowledge-sync的npm test验证抽取、来源约束和待审导入；npm run audit:corpus报告应用资源，不代表数据库库存。
tools/rag-eval的npm test验证评估器；npm run evaluate:published测试发布主题，npm run evaluate:development运行60条固定作者开发查询。
同主题变体带groupId，报告记录split、labelAuthor和前后语料指纹。修正后的评估器按唯一文档标题计算目标排名，保留所选/候选片段原文、SHA-256及匹配的chunkId/版本，便于回看错误来自哪个具体片段；本地报告因此含公开来源摘录，只保存在忽略目录。此前报告不含这些字段，不能追溯补造。
当前60条只是DEVELOPMENT_ONLY，尚无独立留出或穷举相关片段标签。
quality.mjs提供另行评审的片段Recall@k/Precision@k/MRR、答案正确性与逐断言忠实度计算。片段指标要求穷举相关标签并按文档版本与正文哈希匹配；去重后计分，空分母及未审保持未知。当前尚未提供完整真实标签或质量成绩，不能将计算器测试称为准确率评测。
离线评分入口：`node tools/rag-eval/quality-cli.mjs 报告.json 标签.json 3`。标签需schemaVersion=1、corpusSha256与报告完全一致；cases中按id给exhaustive=true、relevant片段版本/哈希数组，可附answerReview（correctness及逐断言support）。报告缺失或歧义的片段身份拒绝计分；缺标签、未评回答单列，不自动补标。标签与含正文报告仍保存在本机，不公开患者数据。
新评估快照包含全部批准片段正文，不仅召回候选。`review-packet-cli.mjs`将其转为本机待评审包：逐题查看完整冻结语料、标注相关片段和参考答案；初始exhaustive=false，不根据模型分数或预设标题自动标注。旧报告没有全部正文时拒绝生成，不能把未召回片段漏出召回率分母。输出文件不可覆盖旧评审。
临时禁用重排且require-semantic=true时，RRF候选中的纯词法命中仍保留诊断，但最终只采用同时在原向量阈值候选内的片段，纯词法项标记unconfirmed_lexical_only_without_rerank。此约束不提高阈值、不按症状写特殊分支，也不代表医学适用性已验证；可能损失仅词法可找到的有效资料，须用固定集复测。启用重排及其他本地配置不变。
质量评分输出同时保留标签版本、标注者、审核状态、临床审核状态及数据划分；缺失记UNSPECIFIED。作者诊断草案不能因计算出了数值就变成独立验收，开发集不能改名为留出集。
离线评分入口：`node tools/rag-eval/quality-cli.mjs 报告.json 标签.json 3`。标签需schemaVersion=1、corpusSha256与报告完全一致；cases中按id给exhaustive=true、relevant片段版本/哈希数组，可附answerReview（correctness及逐断言support）。报告缺失或歧义的片段身份拒绝计分；缺标签、未评回答单列，不自动补标。标签与含正文报告仍保存在本机，不公开患者数据。
最终选留片段也单独保存与语料快照匹配的chunk版本引用，不依赖候选列表间接查找。相同标题存在多个匹配版本时保留全部匹配，不任取第一份；无匹配时为空，不能伪造溯源。这些引用只证明片段身份，不证明适用性或回答支持。
评估快照和片段引用保留数据库提供的章节路径、序号与正文位置，帮助区分「腹痛章节中的胸痛警示」与胸痛通用资料；旧报告缺字段仍记为空或未知，不按标题推造上下文。
`cases-development-60-v2.json`保留v1全部查询和主题，仅更新新发布文档标题；两版标签均保留。可用 `node cli.mjs cases-development-60-v2.json`复验新稿，不以旧标题结果代替新版本质量验证。
单目标文档命中率与MRR不能称完整Recall或Precision；额外候选需核对片段及条件。检索p50/p95不是整个患者回答耗时，依赖失败单独记录。
报告仅存本机reports/rag/，不上传令牌或患者对话；报告包含检索到的来源片段。开发集通过不证明最终回答受支持，不能以调整标签掩盖失败。
主动禁用重排单独计为rerankSkippedCases；只有语义READY且模式为HYBRID_QDRANT_UNRERANKED才计入配置模式的运行通过，既不算供应商故障，也不算严格重排通过。configuredModeTargetPasses仅表示当前配置的目标文档命中，非答案质量；原passed与CLI严格非零退出行为保留。
