# RAG 设计与验证

## 范围

RAG 使用数据库中已审批的正文，不在回答时抓取来源 URL。默认由 Java 工作流调用检索；启用 `AI_AGENT_MODE=ENABLED` 后，普通咨询分支允许模型通过 Function Calling 选择只读检索工具，实际执行仍经过服务器网关。急症、分诊评估与预约不交给模型决策。检索分数不是诊断概率；资料命中、答案实际采用和人工审核是三个不同状态。

Agent 查询仅接受服务端冻结的本轮患者原话，或经来源校验的本人、当前、肯定症状原词；暂不开放自由查询改写。它可以选择检索顺序，但不能修改 BM25/Qdrant/RRF/重排的实现、阈值或资料审批状态。无结果仍保留真实的未命中状态，不因 Agent 执行成功变为有依据。规划失败回退原工作流，最终生成与支持核对链不变；此接入不代表召回率或忠实度已经提高。

公开仓库提供代码、来源登记、开发评估集，以及 `knowledge/corpus/` 下11篇示例正文与必要来源文本；不携带患者数据、本机报告或其他未经许可核实的资料。空数据库可以启动，但没有已审批资料时不能生成资料支持的回答。医学规则、中文整理稿与模型回答均未经专业临床审核。

## 离线：来源到可检索片段

```text
登记来源与许可 → 抓取快照 → 抽取清洗 → 人工整理与核对
  → 校验资料包 → 待审入库 → 管理员审批 → 切分与索引 → 固定评估
```

### 资料格式与目录

- `knowledge/sources/`：抓取的本机网页快照。
- `knowledge/corpus/`：按业务主题组织的 Markdown 正文及同目录来源文件。
- `knowledge/releases/`：本机发布回执。
- `reports/knowledge-sync/`、`reports/rag/`：采集状态和评估报告。

11篇示例正文及必要来源文本已公开；本机原始网页缓存、发布回执和评估报告被 Git 忽略。目录与许可边界见 [知识目录](../knowledge/README.md)和[语料许可](../knowledge/LICENSE.md)。

Markdown 最小头使用两行 `---` 包围严格 JSON，声明文档身份、待审状态和 provenance 文件哈希。完整来源、采集日期、适用范围、许可和章节来源记录放同目录 `provenance.json`，绑定全部声明的来源快照。校验器拒绝缺失文件、路径穿越和哈希漂移；旧内联元数据格式仍可读取，但不能与外部元数据并存。只有头部之后的医学正文进入切分和向量化。

采集工具执行 robots、重定向和限速检查；失败不补造正文或日期。NLM 健康主题来源仅抽取允许的 topic-summary 区域，不能把整站或第三方内容视为可复用。许可和医学适用性仍需人工核验。

### 导入、审批与撤回

管理员页面支持同时选择 Markdown、provenance 和全部来源快照；本地 CLI 默认只校验，加 `--apply` 才创建待审记录。CLI 只访问配置的本机 API，拒绝重定向，令牌通过 `KNOWLEDGE_ADMIN_TOKEN` 注入，不自动审批。

MyBatis 保存正文、来源/适用元数据、当前审批状态和导入审计清单。清单保留来源文件名/ID/哈希、正文哈希及抽取告警；原始网页正文与章节到来源的逐段映射仍在本地。客户端提交的哈希不是服务端独立来源认证。

导入用标题与正文生成稳定幂等键。服务端在同一事务中保存请求指纹和资料：相同请求重放返回原记录，相同键但元数据不同返回 409；数据库唯一键裁决并发。导入不会覆盖或审批旧稿。

待审资料不参与检索；许可 pending/restricted 不可发布。数据库提交成功后更新目录和索引缓存，失败不得只在内存显示成功。撤回先持久化待审状态，再移出活动缓存；旧 Qdrant point 可以暂存，但后续请求按当前批准集合过滤。历史回答和在途快照不追溯删除。

应用运行资源不包含历史医学摘要；测试资源中的旧稿仅作工程夹具。仓库 `knowledge/corpus/` 另提供11篇待审示例正文、来源元数据和必要纯文本快照，来源许可见 `knowledge/LICENSE.md`。这11篇当前使用权限字段均为 `pending`，可校验、待审导入及离线切分，但不可直接审批到患者检索；公开再分发许可不等于患者端使用或医学审核通过。启动恢复数据库现有状态，不自动导入或审批仓库示例。原始网页缓存、intake包、发布回执和评估报告仍仅保留本机。

### 切分与索引

`MarkdownChunker` 按标题和段落切分，同章节短段依次打包、不跨标题；长段最多 420 个 Unicode 码点，重叠 60 码点，优先句末切开。每片段保留文档/内容版本、稳定 chunk ID、章节路径、原始位置、正文哈希和切分策略。切分成功不证明医学条件完整，仍需片段级审核。

JDK17编译后运行 `java --class-path backend/target/classes tools/knowledge-sync/ChunkInspection.java knowledge/corpus`，使用应用的同一切分器逐篇检查原文覆盖、段落边界、每段对应的章节路径、偏移、哈希与确定性。`--self-test`包含正确/错误章节路径与段落跨片段的正反例。当前11篇得到78片段、26片段短于80码点、最长207码点、实际没有长段重叠窗口；420/60是配置上限，不是此次语料的实际片段长度或重叠量。这是机械审计，不能代替适用条件和警示语的医学复核，也不能凭短片段数量单独断定召回质量。

BM25 和 embedding/Qdrant 使用同一批准片段集合：

| 索引 | 实现与生命周期 |
| --- | --- |
| BM25 | 进程内统计索引，随批准正文缓存更新；不把人工预设答案当检索结果 |
| Qdrant | embedding 向量及溯源 payload；幂等 point ID，查询校验模型、版本、哈希和活动语料身份 |

新 collection 可配置 HNSW；小数据可能全扫描。已有 collection 不会因应用默认值变化自动改配置，向量存储成功也不等于查询使用了 HNSW。应查看实际 collection 配置及 `indexed_vectors_count`，缺字段记未知，不推造性能结论。

`KnowledgeIndexBuildRunner` 通过 `ai.knowledge.offline-index.enabled=true` 显式启用，复用批准语料同步入口；`ai.knowledge.offline-index.manifest-path` 指定本地清单。清单含片段身份、模型、语料指纹和实际 collection 配置，不含患者问题或正文；数量或身份不一致拒绝成功。

## 在线：多路召回到回答

```text
本轮问题与有界上下文
  → BM25 候选 + embedding/Qdrant 候选
  → 单一 RRF 融合 → 可选 rerank → 阈值和依赖闸门
  → 有界证据与章节 → 模型生成 → 引用校验与支持核对
  → 保存回答、实际采用资料及 trace
```

模型不负责补救召回失败。query plan 的候选改写仅作诊断，不宣称在线已使用 LLM query rewrite。急症安全闸门独立执行，不等待检索/生成，模型不得覆盖风险限制或预约权限。

### 融合、重排与降级

阈值、候选深度与依赖要求见 [应用配置](../backend/src/main/resources/application.yml)。日常配置默认关闭重排，集合使用 `ai_hospital_knowledge_v2`；不需要切换profile。可选 `rag-live` 默认要求语义配置可用、不要求重排；普通配置可以允许带明确标识的本地降级。依赖失败必须区别于资料无命中。更换集合不会自动迁移已有向量，复用其他集合须显式配置。

- 开启重排：RRF 候选送重排服务，最终每份资料最多保留一个片段。
- 显式关闭重排：同时设置 `AI_RERANK_ENABLED=false` 和 `AI_RETRIEVAL_REQUIRE_RERANK=false`。向量查询成功时，最终 K 项先保留向量前 `ceil(K/2)` 项，其余从 RRF 顺序补足，按片段身份去重。
- 若同时要求语义可用，未重排路径最终只接纳通过原向量阈值的候选；纯词法候选仍保留诊断，不冒充已确认依据。

禁用重排记录 `DISABLED_BY_CONFIGURATION` / `UNRERANKED`，不计供应商故障，也不计严格重排通过。该模式必须单独评估，不能沿用重排模式成绩。相关度和规则参考分值都不是经过校准的概率。

诊断记录各路排名、标题/正文 BM25 词项贡献、重排分数、选择理由和片段版本。片段章节由本轮批准正文按完整身份映射，不相信向量 payload 中的单方声明；身份或章节歧义保持未知。标题不同可能来自同一警示条件，但高分不能证明病因或个人适用性。

### 生成与展示边界

检索片段与章节是不可信数据。生成和独立模型支持核对共用适用性约束：病程、护理、病因和就医条件不得跨症状背景套用；伴随警示不能证明主要疾病。提示约束和第二次模型核对都不能保证医学正确。

结构校验拒绝重复 JSON 字段、重复引用和带引用的 LIMITATION；药品过滤、UNSAFE_OUTPUT、EVIDENCE_BLOCKED 和安全规则约束见 [架构说明](ARCHITECTURE.md)。没有合格证据时，不生成缺乏支持的个体化诊断、用药或预约结论；依赖异常展示服务失败，不伪装为医学拒答。

患者只看到引用完整性通过、支持核对 PASSED 且明确采用的唯一资料；检索到但未采用的片段另行折叠标注。缺历史记录不补造引用。链接仅允许 HTTP/HTTPS、拒绝嵌入凭据，正文转义展示。

SSE 推送阶段进度，正文检查后整段返回，不是逐 token 展示。用时区分客户端请求计时和持久化轮次耗时，不以模型阶段耗时冒充完整请求耗时。

## 评估：工程回归与人工质量分开

普通 JDK 17 Maven 测试使用模型桩，不调用供应商；带供应商凭据的在线检索评估须显式设置 `AI_RAG_LIVE_TEST=true`。另有 `QdrantLiveIntegrationTest`：CI 以合成二维 embedding 对真实隔离 Qdrant 执行新增、增量、查询及撤回后的活动集合过滤；本机可用 `-Dtest=QdrantLiveIntegrationTest -Dai.test.qdrant-url=http://127.0.0.1:<隔离端口>` 单独运行。它不调用供应商，也不使用医学资料；通过只证明向量接口与活动集合闸门的机械行为，不是召回率或医学质量。

工具入口：

```powershell
# 来源抽取与导入校验
cd tools/knowledge-sync
npm test
npm run audit:corpus
# 评估器测试及本机在线检索（需 RAG_EVAL_PASSWORD，默认后台 8081/api）
cd ../rag-eval
npm test
# 审批公开11篇示例资料后，运行当前语料的作者主题开发集
npm run evaluate:public
```

在线检索评估冻结前后批准语料指纹，并保存完整批准片段正文及版本/哈希。运行前先校验目标标题都存在于当前已审批语料；旧评估集遇到新语料标题会明确拒绝，不能把过期标签算成召回失败。报告只留本机。`cases-public-corpus-development.json` 的12个查询只做作者标注的文档主题冒烟检查；作者看过旧排名的历史查询集也不是独立留出集。单目标标题命中不是完整召回率，当前11篇尚无独立穷举片段标签。

| 评价对象 | 计算要求 |
| --- | --- |
| BM25 / Qdrant / RRF / 最终片段的 Recall@k、Precision@k、MRR | 同一冻结语料及穷举相关 chunk 标签，完整身份可解析 |
| 无覆盖误选、额外片段、依赖故障、检索延迟 | 单独统计；检索延迟不等于患者回答延迟 |
| 回答正确率、忠实度 | 独立人工答案审核，绑定回答哈希、消息及 trace |
| 分诊参考分值 Brier / ECE | 独立处置正确性标签，不能用模型自报代替 |

离线评分入口为 `node tools/rag-eval/quality-cli.mjs 报告.json 标签.json 3`。标签须绑定语料 SHA-256，逐题声明 `exhaustive=true` 与相关片段身份；缺正文、语料漂移、身份歧义或非穷举标签拒绝计算对应指标。逐题保留 missed/extra 身份，不能按预设标题自动补标。

`review-packet-cli.mjs` 从完整冻结语料生成检索评审包，初始不自动标相关；旧候选-only 报告不能充当完整评审语料。

答案人工评审流程：

```powershell
node tools/rag-eval/conversation-review-packet-cli.mjs 会话.json reports/rag/review.json
# 独立审核者填写后
node tools/rag-eval/answer-review-cli.mjs reports/rag/review.json
```

评审包绑定回答、患者消息、最近 5 轮/4000 字符窗口和实际采用来源；缺少或漂移的 trace/哈希标为不可评，不向审核者展示模型核对结论。输出仅允许写入被忽略的 `reports/rag/`，不覆盖旧文件。

整份答案忠实度要求 `claimsExhaustive=true`，且逐断言审核；SUPPORTED 断言须引用实际采用的资料。部分审核、无标签或无事实断言保持未知。纯检索报告没有答案快照，不能计算回答正确率/忠实度。工具不认证评审人的独立性或临床资质；未脱敏会话不能公开提交或外发。

## 尚未完成

- 专业临床审核、独立留出集和完整答案质量验收。
- 不可变审核版本、跨实例缓存通知、知识修改历史与自动留存策略。
- 完整私有资料包版本化交付、索引原子发布与回滚。
- 实际 collection 的精确/近似搜索对比、容量与全链路性能验证。
- 真实 HIS、医院身份系统及上线隐私制度。

历史报告和本机数量不作为仓库默认能力或医学效果承诺。
