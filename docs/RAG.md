# RAG 设计与验证

## 范围

离线回答评审包使用同一五轮/4000字符完整消息窗口，不保留孤立的助手开头；当前消息本身超限则不生成可评分评审项。若本轮保存了NARRATION上下文淘汰计数，按实际计数重建更小窗口并标记来源；旧记录仅标记字符窗重建，不能冒称供应商实际Prompt。损坏或矛盾的计数使该项不可评审，而不是自动扩大窗口。

评审身份哈希另绑定回答、trace、患者窗口、引用快照、分诊与服务快照；答案和分诊标签各自引用该哈希。同一句回答若换了患者历史、证据或科室，不得借用旧标签。旧评审包缺少此绑定时需重新生成并复核，不自动补签；哈希只能发现绑定后的漂移，不认证原始数据、评审者或临床正确性。

回答发送前的证据窗口按整份引用JSON≤4000字符选择，不对子串做截断；更低的上下文估算预算可能淘汰末位整片，引用校验只接受实际发送的ID。全部证据无法容纳时报告上下文预算阻断，不能将其写成资料未检索到。预算与供应商实际Token分开记录，规则、审批、检索阈值不因预算而放宽。

RAG 使用数据库中已审批的正文，不在回答时抓取来源 URL。默认由 Java 工作流调用检索；启用 `AI_AGENT_MODE=ENABLED` 后，普通咨询分支允许模型通过 Function Calling 选择只读检索工具，实际执行仍经过服务器网关。急症、分诊评估与预约不交给模型决策。检索分数不是诊断概率；资料命中、答案实际采用和人工审核是三个不同状态。

Agent 的症状查询白名单只包含来源校验后的本人、当前、肯定症状原词；从已抽取症状事件的患者原句不再整句加入白名单，因此否定、他人或既往症状不能借原句绕过事件筛选。没有任何症状事件且意图为一般健康知识时，才允许使用当前原问题作为查询。空白名单拒绝全部 Agent 医学检索，不解释为无限制查询；旧工作流仍按自身证据规则处理。暂不开放自由查询改写。Agent可以选择检索顺序，但不能修改BM25/Qdrant/RRF/重排的实现、阈值或资料审批状态。无结果仍保留真实未命中状态，不因Agent执行成功变为有依据。规划失败回退原工作流，最终生成与支持核对链不变；此接入不代表召回率或忠实度已经提高。

医学检索query为空（例如只有挂号/医生目录请求）时，回答链不发送空词或目录词到医学RAG，也不调用最终回答生成模型；记录`retrievalStatus=NOT_APPLICABLE`、生成阶段`NOT_RUN`，返回固定提示并单独展示已取得的目录状态。前置意图抽取或工具规划仍可能用模型，因此“未调用最终回答模型”不等于“本轮任何阶段都未调用LLM”。非空医学查询即使Agent没有预取结果，也继续既有检索和回答流程；目录数据不算医学证据。

经校验的纯服务意图通过`PreparedEvidence.purpose=SERVICE_ONLY`传递给回答链：无症状事件、无冲突且只有目录/预约意图时，科室名和排班修饰词不作为医学查询。空Optional预取结果本身没有这种含义，未知或症状混合请求仍走原检索路径。该分类沿用抽取模型输出，不代表意图识别准确性已验收；原话急症检查优先。

`INTENT_ROUTE`执行事件仅记录受控的意图枚举及允许工具代码，供本轮流程解释使用；不写入患者原话/症状字段，不证明模型实际执行了工具，也不参与风险、分诊和预约决策。

公开仓库提供代码、来源登记、开发评估集，以及 `knowledge/corpus/` 下11篇示例正文与必要来源文本；不携带患者数据、本机报告或其他未经许可核实的资料。空数据库可以启动，但没有已审批资料时不能生成资料支持的回答。医学规则、中文整理稿与模型回答均未经专业临床审核。

## 离线：来源到可检索片段

```text
登记来源与许可 → 抓取快照 → 抽取清洗 → 人工整理与核对
  → 校验资料包 → 待审入库 → 管理员审批 → 切分与索引 → 固定评估
```

### 资料格式与目录

- `knowledge/sources/`：抓取的本机网页快照。
- `knowledge/corpus/`：按业务主题组织的 Markdown 正文及同目录来源文件。
- `knowledge/releases/`：本机发布回执。
- `reports/knowledge-sync/`、`reports/rag/`：采集状态和评估报告。

11篇示例正文及必要来源文本已公开；本机原始网页缓存、发布回执和评估报告被 Git 忽略。目录与许可边界见 [知识目录](../knowledge/README.md)和[语料许可](../knowledge/LICENSE.md)。

Markdown 最小头使用两行 `---` 包围严格 JSON，声明文档身份、待审状态和 provenance 文件哈希。完整来源、采集日期、适用范围、许可和章节来源记录放同目录 `provenance.json`，绑定全部声明的来源快照。校验器拒绝缺失文件、路径穿越和哈希漂移；旧内联元数据格式仍可读取，但不能与外部元数据并存。只有头部之后的医学正文进入切分和向量化。

采集工具执行 robots、重定向和限速检查；失败不补造正文或日期。NLM 健康主题来源仅抽取允许的 topic-summary 区域，不能把整站或第三方内容视为可复用。许可和医学适用性仍需人工核验。

### 导入、审批与撤回

管理员页面支持同时选择 Markdown、provenance 和全部来源快照；本地 CLI 默认只校验，加 `--apply` 才创建待审记录。CLI 只访问配置的本机 API，拒绝重定向，令牌通过 `KNOWLEDGE_ADMIN_TOKEN` 注入，不自动审批。

MyBatis 保存正文、来源/适用元数据、当前审批状态和导入审计清单。规范化Markdown导入时，工具从受绑定的provenance生成清单，保留文档ID、provenance与正文哈希、来源文件名/ID/哈希及抽取告警；早期导入的旧记录可能没有该清单，不能仅凭`READY`推断完整。原始网页正文与章节到来源的逐段映射仍在本地。客户端提交的哈希不是服务端独立来源认证。

导入用标题与正文生成稳定幂等键。服务端在同一事务中保存请求指纹和资料：相同请求重放返回原记录，相同键但元数据不同返回 409；数据库唯一键裁决并发。导入不会覆盖或审批旧稿。

精确算法为 `sha256(title + NUL + body)`，服务端请求指纹另追加 `NUL + 序列化metadata`；采用传入字段的UTF-8字节，不在哈希前统一标点或删除空白。正文或标题改变通常是新键，同键而元数据改变是冲突。该契约保障精确重试，不提供语义或近重复去重；修改规范化策略需要版本与旧回执兼容设计。

待审资料不参与检索；许可 pending/restricted 不可发布。MyBatis知识写入与目录/发布版本在同一事务提交，失败一起回滚。实例在入口读版本并重载一致快照；撤回后的下一次读取不继续使用该实例旧批准缓存。数据库无法核验时返回 `KNOWLEDGE_STORE_UNAVAILABLE`，不伪装成无资料。检索结束前发布版本变化时返回 `KNOWLEDGE_SNAPSHOT_CHANGED`、不采用旧候选；新增待审草稿不会触发该阻断。旧Qdrant point可暂存，按当前批准集合过滤。历史回答不追溯删除，最终检查后发生的变化与后续生成仍存在竞态窗口，并非全流程原子发布。

应用运行资源不包含历史医学摘要；测试资源中的旧稿仅作工程夹具。仓库 `knowledge/corpus/` 另提供11篇待审示例正文、来源元数据和必要纯文本快照，来源许可见 `knowledge/LICENSE.md`。这11篇原件使用权限均为 `pending`，不可直接审批。维护者允许在隔离本机测试库按 `tools/knowledge-sync/README.md` 的显式命令导入、标记仅测试授权并审批；原件不变，测试库 `READY` 不等于临床审核或真实患者发布许可。启动恢复数据库现有状态，不自动导入或审批仓库示例。原始网页缓存、intake包、发布回执和评估报告仍仅保留本机。

### 切分与索引

导入哈希契约由 `KnowledgeImportIdentityTest` 锁定：空白、中文/英文标点和换行改变是新内容键；来源或元数据列表顺序改变会改变请求指纹。输入JSON对象字段顺序在同一Jackson配置下经类型化元数据解析后不改变指纹，这不等于全局JSON规范化或语义去重。没有更改历史键算法。

`MarkdownChunker` 按标题和段落切分，同章节短段依次打包、不跨标题；长段最多 420 个 Unicode 码点，重叠 60 码点，优先句末切开。每片段保留文档/内容版本、稳定 chunk ID、章节路径、原始位置、正文哈希和切分策略。切分成功不证明医学条件完整，仍需片段级审核。

JDK17编译后运行 `java --class-path backend/target/classes tools/knowledge-sync/ChunkInspection.java knowledge/corpus`，使用应用的同一切分器逐篇检查原文覆盖、段落边界、每段对应的章节路径、偏移、哈希与确定性。`--self-test`包含正确/错误章节路径与段落跨片段的正反例。当前11篇得到78片段、26片段短于80码点、最长207码点、实际没有长段重叠窗口；420/60是配置上限，不是此次语料的实际片段长度或重叠量。这是机械审计，不能代替适用条件和警示语的医学复核，也不能凭短片段数量单独断定召回质量。

BM25 和 embedding/Qdrant 使用同一批准片段集合：

| 索引 | 实现与生命周期 |
| --- | --- |
| BM25（默认ES） | `LexicalSearch` 端口接入 Elasticsearch，Lucene负责倒排与BM25；内置CJK分析器，标题/正文独立字段，k1=1.2、b=0.75、标题boost默认2，尚未调优 |
| BM25（轻量选项） | `AI_LEXICAL_BACKEND=memory` 选择不可变内存postings，中文2/3字符gram；`searchDetailed` 提供访问计数，不代表质量或延迟指标 |
| Qdrant | embedding 向量及溯源 payload；幂等 point ID，查询校验模型、版本、哈希和活动语料身份 |

新 collection 可配置 HNSW；小数据可能全扫描。已有 collection 不会因应用默认值变化自动改配置，向量存储成功也不等于查询使用了 HNSW。应查看实际 collection 配置及 `indexed_vectors_count`，缺字段记未知，不推造性能结论。

`KnowledgeIndexBuildRunner` 通过 `ai.knowledge.offline-index.enabled=true` 显式启用，复用批准语料同步入口；`ai.knowledge.offline-index.manifest-path` 指定本地清单。清单含片段身份、模型、语料指纹和实际 collection 配置，不含患者问题或正文；数量或身份不一致拒绝成功。

## 在线：多路召回到回答

### ES索引和失败边界

ES 8.17.6 使用原生 [CJK分析器](https://www.elastic.co/guide/en/elasticsearch/reference/8.17/analysis-cjk-analyzer.html)，不是医学词典。例如“急性心肌梗死”实测为“急性/性心/心肌/肌梗/梗死”，不保留完整术语；医学词典、同义词和分析器消融仍待评估。标题boost默认2不是经验效果承诺。

首次查询某批准语料快照时，以稳定片段内容身份生成文档ID，语料排序后的ID及分析策略版本生成SHA-256索引后缀。按100片段分批bulk写入，逐项检查状态并使用 `refresh=wait_for`，全部成功才在本进程标为可查询。进程重启可复用同名索引并幂等写入；存在索引须通过schema/快照元数据检查，不覆盖其他索引。审批新增、正文变化和撤回导致下一次查询选择新的快照；这是请求触发同步，不是后台增量任务或原子alias发布。旧快照不自动删除，显式维护工具见下节。批准缓存通过数据库版本读穿刷新，无推送通知；升级/直接SQL修改边界见架构文档。

### 旧ES快照维护

`scripts/es-snapshot-maintenance.mjs` 默认只读，必须显式指定本机ES地址和至少一个保留索引完整名称。工具读取索引元数据，不读取医学正文、查询或患者数据；检查名称的64位哈希后缀、schema/snapshot绑定、UUID、创建时间和无alias状态。只有年龄至少24小时且非保留的索引才可列为候选。该年龄不是“无在途请求”的证明，也不自动推断哪个版本仍在使用。

```powershell
# 先按ES Get index API盘点实际索引名称，确认当前版本、回滚版本和其他部署共用情况。
# $currentIndex / $obsoleteIndex 必须是核实后的完整名称，不允许星号。
node scripts/es-snapshot-maintenance.mjs --url http://127.0.0.1:9201 --keep $currentIndex

# 停止所有共用该前缀的应用实例及其他索引维护程序，等待在途读取退出；备份所需索引。
# 保留多个版本时重复 --keep。先不加 --apply，核对同一份删除选择。
node scripts/es-snapshot-maintenance.mjs --url http://127.0.0.1:9201 --keep $currentIndex --delete $obsoleteIndex
node scripts/es-snapshot-maintenance.mjs --url http://127.0.0.1:9201 --keep $currentIndex --delete $obsoleteIndex --apps-stopped --apply
```

执行前重新核对所有保留/待删索引UUID及创建时间；只对逐个完整名称发送DELETE，不更改集群通配删除保护。`--apps-stopped` 是操作者确认，不是自动检测或分布式租约：其他管理员并发替换索引仍有竞态，不能在线自动回收。失败不重试、不继续下一项，已完成的删除不回滚，响应不确定时先盘点再决定。删除会丢失该索引的片段副本；可由仍获准的数据库正文重建，已撤回资料不应为恢复旧索引而重新审批。API Key仅从 `AI_ELASTICSEARCH_API_KEY` 读取，不输出供应商正文。工具仅支持loopback，远端集群需另经运维流程。接口依据：[Get index](https://www.elastic.co/guide/en/elasticsearch/reference/8.17/indices-get-index.html)、[Delete index](https://www.elastic.co/guide/en/elasticsearch/reference/8.17/indices-delete-index.html)。

隔离集成验证：设置 `ES_SNAPSHOT_TEST_URL=http://127.0.0.1:<测试ES端口>` 后运行 `node scripts/test-es-snapshot-live.mjs --apply`。脚本在真实ES创建唯一 `testlexical-<uuid>` 前缀的两个合成索引，核对真实时钟下近期删除被拒绝，再以注入48小时的测试时钟验证真实DELETE及保留索引UUID不变，最后按明确名称/UUID清理自己的索引。测试时钟不作为维护CLI选项，不降低日常24小时门槛；该测试不是实际等待24小时或在线租约验证。不得对共享患者环境运行，失败不自动重试；CI提供独立服务。2026-10-16隔离ES8.17.6实跑通过。

查询通过 `multi_match` 搜索标题和正文；ES专用 `AI_ELASTICSEARCH_MIN_SCORE` 默认0，不套用内存BM25的0.28。ES结果再次校验文档ID、当前快照原文及来源；部分结果、超时和异常响应不采用。故障返回脱敏 `ELASTICSEARCH_*` 状态：连接拒绝、建连超时、请求超时及HTTP状态码分别区分，不保留响应正文；其他解析/传输异常仍归入 `ELASTICSEARCH_UNAVAILABLE`。不自动切到内存；Qdrant和已有语义/重排依赖策略继续独立生效，不能把词法故障当“资料不存在”。后台检索详情、事件及轮次trace保存词法状态，ES没有本地TF解释时不伪造解释项。

本机Compose仅绑定9201，关闭认证仅供开发；远端端点须HTTPS，API Key从 `AI_ELASTICSEARCH_API_KEY` 注入。唯一的非回环HTTP例外是显式 `AI_DEMO_LOCAL_CONTAINER=true`、Docker标记存在、无API Key且目标恰为 `http://elasticsearch:9200` 的本机Compose服务；不同主机/端口/路径/嵌入凭据均不获此例外。应用不能验证外层网络隔离，操作者仍须遵守Compose的回环发布边界。默认离线测试显式使用memory；`ElasticsearchLiveIntegrationTest` 须传 `-Dai.test.elasticsearch-url=http://127.0.0.1:<隔离端口>`，只创建合成语料和唯一测试前缀，按校验后的明确名称清理。该集成测试验证Lucene分析和索引接口，不提供医学召回率或质量结论。

```text
本轮问题与有界上下文
  → BM25 候选 + embedding/Qdrant 候选
  → 单一 RRF 融合 → 可选 rerank → 阈值和依赖闸门
  → 有界证据与章节 → 模型生成 → 引用校验与支持核对
  → 保存回答、实际采用资料及 trace
```

模型不负责补救召回失败。query plan 的候选改写仅作诊断，不宣称在线已使用 LLM query rewrite。急症安全闸门独立执行，不等待检索/生成，模型不得覆盖风险限制或预约权限。

### 融合、重排与降级

阈值、候选深度与依赖要求见 [应用配置](../backend/src/main/resources/application.yml)。日常配置默认关闭重排，集合使用 `ai_hospital_knowledge_v2`；不需要切换profile。可选 `rag-live` 默认要求语义配置可用、不要求重排；普通配置可以允许带明确标识的本地降级。依赖失败必须区别于资料无命中。更换集合不会自动迁移已有向量，复用其他集合须显式配置。

- 开启重排：RRF 候选送重排服务，最终每份资料最多保留一个片段。
- 显式关闭重排：同时设置 `AI_RERANK_ENABLED=false` 和 `AI_RETRIEVAL_REQUIRE_RERANK=false`。向量查询成功时，最终 K 项先保留向量前 `ceil(K/2)` 项，其余从 RRF 顺序补足，按片段身份去重。
- 可选实验 `AI_UNRERANKED_DOCUMENT_DIVERSITY=true`（默认false，日常不必设置）：未重排的剩余槽位优先从不同数据库文档各取首个合格片段；可用文档不足时再按原排名补同文档其他片段，不强制每文档只能一片。分组仅用批准快照中唯一可解析的documentId，不用标题、模型或向量payload猜归属；歧义来源不合并。既有语义预留槽位（包括同文档的两段）、否定排除及要求语义确认的过滤保持不变。此策略避免单份长文占满槽位，但可能增加低相关文档，需片段标签评估，不是相关性或答案支持证明。成功rerank的结果不应用这层多样性。运行信息记录 `unrerankedDocumentDiversity`，旧报告缺项保持未知，不据目标标题计数自动启用。
- 若同时要求语义可用，未重排路径最终只接纳通过原向量阈值的候选；纯词法候选仍保留诊断，不冒充已确认依据。

禁用重排记录 `DISABLED_BY_CONFIGURATION` / `UNRERANKED`，不计供应商故障，也不计严格重排通过。评估器的 `passed` 表示**当前配置模式**的依赖与目标资料检查通过，另以 `strictRerankedPasses` 保留严格重排口径；两种模式不可直接合并比较。相关度和规则参考分值都不是经过校准的概率。

embedding 或 Qdrant 的非成功 HTTP 响应在管理员检索状态中分别记录为 `EMBEDDING_HTTP_状态码`、`QDRANT_HTTP_状态码`。HTTP成功但向量数量、序号、数值或维度不合法时记录 `EMBEDDING_RESPONSE_*`；已有集合维度或距离不匹配时记录 `QDRANT_COLLECTION_DIMENSION_MISMATCH`，不覆盖旧集合。连接拒绝、建连/请求超时、无效JSON和传输异常按embedding、Qdrant查点/集合/写入/搜索阶段区分；其余未分类异常保留 `INDEX_UNAVAILABLE` 或 `SEARCH_UNAVAILABLE`。状态仅含固定错误码，不记录供应商响应正文、密钥或患者问题；`configured=true` 只表示参数齐全，不表示调用成功。要求语义检索的运行模式遇到这些故障仍阻断资料依据，不把依赖失败伪装成无资料。

embedding 请求显式指定 `encoding_format=float`，与数值向量解析契约一致，接口参数见[百炼官方说明](https://help.aliyun.com/zh/model-studio/text-embedding-synchronous-api/)。非成功响应仅提取预设白名单中的错误标识及 `model/input/dimensions/encoding_format` 参数名，例如 `EMBEDDING_HTTP_400:InvalidParameter:model`；不保留自由文本 message、未知 code/param 或超长响应。HTTP 400 本身不能证明额度耗尽；根据安全错误标识核对配置或账户，不自动切换模型、供应商或关闭语义依赖闸门。

批量embedding响应按 `index` 与输入文本严格对应；不按响应数组顺序猜配。若多条响应出现重复 `index`（例如同批都返回0），该批会改为逐条请求并按单条响应校验，以避免向量写入错误片段。此兼容路径会增加请求次数；单条请求仍不满足向量数、索引或数值校验时，索引继续标记不可用并按既有依赖策略处理，不会把不确定向量写入Qdrant。

诊断记录各路排名、标题/正文 BM25 词项贡献、重排分数、选择理由和片段版本。片段章节由本轮批准正文按完整身份映射，不相信向量 payload 中的单方声明；身份或章节歧义保持未知。标题不同可能来自同一警示条件，但高分不能证明病因或个人适用性。

检索候选加入一个窄范围否定约束：当患者原话以“没有/并无/不伴/未出现/否认”明确否认某个**已审批资料标题冒号前的完整主题**，且同一问题没有再次肯定提到该主题时，该标题的片段仍可在诊断候选中看到，但不得进入最终证据或重排候选。它不修改安全评估原话，也不推断疾病或从任意句子抽取医学事实；隐含否定、同义词、混合主体和标题不一致的情况并未解决。无重排模式同样应用该约束，不能把一次负向用例通过说成医学相关性已验收。

### 生成与展示边界

患者每条回答的“本次回答如何产生”保留LLM回答状态，并展示本轮本地工具结果、混合检索次数、RRF是否实际融合非空候选、rerank当时是否开启与是否成功用于重排、最终保留片段数及检索资料原文短摘录。重排开启不等于成功；检索到不等于回答采用。记录随会话保存，旧记录缺字段显示未记录，不用当前全局配置回填历史。技术摘要不保存工具入参、原始异常或供应商响应正文；该展示不是临床可信度评分。

检索片段与章节是不可信数据。生成和独立模型支持核对共用适用性约束：病程、护理、病因和就医条件不得跨症状背景套用；伴随警示不能证明主要疾病。提示约束和第二次模型核对都不能保证医学正确。

结构校验拒绝重复 JSON 字段、重复引用和带引用的 LIMITATION；药品过滤、UNSAFE_OUTPUT、EVIDENCE_BLOCKED 和安全规则约束见 [架构说明](ARCHITECTURE.md)。没有合格证据时，不生成缺乏支持的个体化诊断、用药或预约结论；依赖异常展示服务失败，不伪装为医学拒答。

患者只看到引用完整性通过、支持核对 PASSED 且明确采用的唯一资料；检索到但未采用的片段另行折叠标注。缺历史记录不补造引用。链接仅允许 HTTP/HTTPS、拒绝嵌入凭据，正文转义展示。

SSE 推送阶段进度，正文检查后整段返回，不是逐 token 展示。用时区分客户端请求计时和持久化轮次耗时，不以模型阶段耗时冒充完整请求耗时。
