# 项目架构

Spring Boot 单体按业务模块组织 api、application、domain、infrastructure；当前不是完整 DDD、微服务或多 Agent 编排。

## 模块

| 模块 | 职责 |
| --- | --- |
| identity | 演示登录 |
| triage | 多轮会话、危险信号、分诊版本、模型回答、人工导诊 |
| booking | 模拟预约、资格校验、幂等与原子扣号 |
| catalog | 科室、医生、模拟号源 |
| knowledge | 资料、BM25、Qdrant、融合与重排 |
| tools | 本地工具执行器与 MCP 子集入口 |
| observation | 统计与调用记录 |
| shared | API 契约、身份校验、异常和公共基础设施 |

依赖方向为 api → application → domain 接口，infrastructure 提供数据库与外部服务实现。仍有共享契约和跨模块直接依赖，不宣称完全隔离。

## 请求流程

会话服务读取当前消息与有界历史，执行风险和流程判断。危险信号由安全规则接管；普通路径显式查询知识、科室与号源，再调用模型。检索无结果时可以进入一般问答路径，不能据此生成缺乏依据的具体分诊结论。历史分诊版本保留快照。

患者流程调用进程内工具执行器，没有模型自主选择工具的循环。管理员认证的 /mcp 共用执行器，提供列表与调用子集。

## 数据一致性

MyBatis Mapper 执行 SQL，默认 H2；MySQL profile 的真实联调尚未完成。模拟预约在事务中以条件更新扣号，并使用幂等键防重复创建。前端展示的号源不等于锁号，后端须再次核验预约资格。

本人资料与聊天记录不是正式病历。没有医生工作台、真实 HIS 或医院实时人工值守。

知识正文、审批状态与来源元数据通过 KnowledgeDocumentStore 端口及 MyBatis 实现保存。检索缓存从数据库重建；新增失败回滚缓存，审批写入成功后才发布。结构化资料的许可声明未解决时不能发布；声明不是临床或法律认证。MarkdownChunker 生成章节与位置溯源，BM25和Qdrant共享批准正文；Qdrant召回校验point id与payload是否符合请求快照，不证明医学适用性。

## 生成与安全边界

2026-10-07确认的权限边界：普通ADMIN的调用观测接口通过TechnicalCallView白名单投影，只返回调用标识、时间、用途、模型、耗时、用量与工具成功/错误存在状态；不返回患者身份、工具入参、结果正文、标签或原始错误。持久化原记录不删除。旧用量0为占位，接口返回null，页面显示未知。此投影不代表已实现全链路敏感数据授权；人工导诊摘要权限、访问留痕和独立逐轮trace仍需完成。未开放批量患者文本导出，未制定自动清理期限。

本批当前源码隔离JDK17、无AI_*的clean test：287项，零失败/错误、1外部用例跳过；前端构建通过。测试核对ADMIN投影、PATIENT及未认证拒绝、敏感字段不序列化、原存储不变及已知/未知用量。原8081尚需加载本批后验证HTTP与浏览器，不将作者测试称为独立验收。

- TriageSafetyPolicy 评估危险信号，模型不能解除风险和预约闸门。
- BM25/Qdrant 阈值、RRF 和 rerank 筛选片段，相关性不代表医学适用性。
- 模型提示词把患者输入与资料声明为不可信数据。
- 输出检查拦截部分不安全表达与用药指导，不保证医学正确。
- 紧急 SAFETY_RULE 路径不等待模型，预约服务再次核验限制。
- SSE 推送处理阶段；正文完成检查后一次返回，尚非逐 token 输出。

规则与中文映射未经临床审核，未命中不能排除急症。外部调用故障必须与无资料区分，降级不能标成模型调用成功。
