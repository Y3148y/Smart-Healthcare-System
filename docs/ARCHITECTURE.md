# 架构与业务边界

## 组织方式

`StructuredDecisionModel` 是旧的多科室白名单方向提议，不是安全风险判定。其请求也使用完整限窗、输入/本轮预占预算和不可信名单消息，不再拼接累计症状全文、截取单条历史或发送候选原因。记录真实返回用量与固定失败码；缺端点跳过，不使用SDK默认供应商，长度截断等非STOP返回拒绝。原规则科室候选和风险流程未改，也未宣称经过临床验证。

活动轮次的对话模型输入还执行累计估算预占：`TurnTraceContext.reserveContext` 在同一共享trace列表上原子核算，显式恢复的工作线程共享额度；抽取、各次工具规划、生成、核对发送前均预占，后续不能抬高本轮上限。配置 `AI_TURN_INPUT_ESTIMATE_BUDGET` 默认262144，额度不足或无法继续跟踪时明确阻断。不退款超时/校验失败的预占，累计数与实际供应商Token/账单分开。它只是当前进程内活动trace的输入控制，不是持久化月度/跨实例配额，不涵盖Embedding、rerank和输出费用；独立无trace调用只受单次上限约束，旧记录无累计字段仍未知。医学规则与预约闸门不因额度而放宽。

回答侧上下文由 `triage.infrastructure.llm.ContextAssembler` 组装：系统约束不裁，本轮患者消息不截断，最近最多五轮对话累计≤4000字符；知识引用按完整JSON累计≤4000字符选择，ID/哈希不改。可配置的总输入估算预算先淘汰完整旧轮次，再淘汰末位完整证据；无法保留必需输入或所有证据均不能容纳时显式阻断，不伪装成无检索结果。核对器请求发送前也检查预算。UTF-8字节加消息开销仅为估算，不是实际Token或模型专用分词器；技术Execution保留预算和淘汰计数，旧记录没有该字段即未知。

项目采用 Spring Boot 分层单体，按业务模块划分 `api → application → domain`，`infrastructure` 实现数据库和外部服务端口。部分共享契约和跨模块直接依赖仍然存在。

| 模块 | 职责 |
| --- | --- |
| identity | 本地演示登录与身份签发 |
| triage | 多轮会话、风险规则、分诊版本、模型回答 |
| knowledge | 文档持久化、切分、BM25、向量检索、融合与重排 |
| catalog | 科室、医生、排班与模拟号源 |
| booking | 预约资格、事务扣号、幂等回执 |
| patient | 本人自述资料、版本冲突控制 |
| review | 人工申请、摘要授权、访问审计 |
| observation | 调用记录、脱敏技术投影与统计 |
| tools | 本地工具执行器、管理员 MCP 工具服务及旧接口兼容 |
| shared / config | API 契约、异常、身份校验、数据库初始化 |

## 请求流程

`TriageConversationService` 负责身份、同会话并发控制和持久化；`TriageWorkflow` 协调一轮计算，`WorkflowRouter` 复用原规则返回类型化 `RouteDecision`。风险规则优先于检索和模型；急症路径直接给出安全提示并停止普通预约。普通咨询可以追问或回答一般知识，分诊推荐还需满足证据与业务条件。普通咨询的检索、生成与审核由 `GuidanceAnswerService` 承担，固定安全/合规回复仍在原策略中；组件读写边界见 [Agent与工作流](AGENT.md)。

普通咨询默认启用 `AgentWorkflowCoordinator`，由模型在受控范围选择只读工具；关闭Agent、规划失败或走其他业务分支时，由 Java 工作流显式调用 `HospitalToolExecutor`。管理员认证的 `/mcp` 共用执行器，支持2025-11-25无状态Streamable HTTP工具服务，保留旧自定义元数据入口；官方SDK真实HTTP互操作测试及其能力/认证边界见[Agent说明](AGENT.md#mcp-工具服务与官方客户端)。患者流程仍没有通过MCP客户端执行工具。

LangChain4j 提供消息类型、模型响应和 OpenAI-compatible 客户端。`OptionalNarrationModel` 使用消息列表构建多轮提示；显式思考/JSON 请求参数通过 `ConfiguredChatTransport` 适配。项目没有接入 Spring AI。

## 存储与一致性

`triage_fact_snapshot` 保存来源校验后的模型观察提议（不是临床事实）。`SessionFactStore` 在会话锁下重验活动轮次、期限、原话窗、Schema和引用，绑定源窗/快照SHA-256与状态版本；同轮重复提议可重放，不同提议不能覆盖。读取只关联COMPLETED轮次，暂存/失败/过期轮次不可见；快照与轮次/回答同事务提交。无快照旧会话返回version0，表示LEGACY/UNKNOWN。快照上限500观察、100冲突、262144字符，超限或损坏显式回退，不静默删旧观察。

`SessionEventTimeline`从原观察派生稳定事件ID及来源绑定的唯一显式更正关系；旧观察追加保留，歧义不猜测。`IntentRouting`将复合意图分类并在明确缺主体/时间时生成最多两个通用问题；窗口外本人记录仅提示再次确认现在是否仍存在，不外发旧医学文本，不将历史CURRENT变成当下事实。安全规则仍检查原话，不使用更正投影解除风险。任意事件、同义词与发作批次消歧仍非已实现能力。

`pending_booking_action` 将患者、准备请求键、医生/排班指纹、会话消息数及分诊版本、DB时间期限和状态绑定为服务端动作；按患者+准备键唯一。`PendingBookingService` 使用READ_COMMITTED，同一会话按会话→动作→目录顺序加锁，重新校验后调用原预约事务，动作CONFIRMED与预约回执/扣号同事务提交。已确认动作重放历史回执，不因后续新症状或过期重复扣号；这不是继续授权新的预约。未确认动作遇状态漂移、过期或取消须重新准备。目录指纹不包含动态余号，余号仍在确认时以条件UPDATE裁决；准备动作不会预留号源。新表为增量结构；旧直约API保留兼容，Agent白名单仍不包含准备、确认或取消写接口。

显式MySQL集成测试还启动两个独立JVM，在就绪屏障后并发确认同一动作或争抢最后一号，分别断言同回执单扣号、单成功且无超卖。它不依赖Java进程内锁；默认离线测试跳过该进程组，用例配置见README。线程回归、跨JVM回归、浏览器响应丢失回归是三类不同证据，不能用其中一项冒称全部性能/故障验证。

词法检索通过 `LexicalSearch` 端口选择适配器：默认Elasticsearch/Lucene BM25，`memory`为轻量与离线测试实现。ES采用批准语料指纹快照，查询触发批量同步，校验每项写入和返回原文身份，失败不静默切换；Qdrant、RRF与重排保持原编排。默认本机9201，医学词典及质量消融尚未完成。生命周期与旧索引清理边界见 [RAG](RAG.md)。

应用通过 MyBatis 使用 MySQL，数据源统一配置在 `application.yml`。H2 仅用于测试；`schema.sql` 初始化表，`DatabaseIndexInitializer` 用 JDBC 元数据检查并幂等创建 trace 索引。旧 H2 数据不自动迁移。

容器 JVM 使用 Asia/Shanghai，与默认 JDBC `serverTimezone` 保持一致；预约时间从 MySQL `TIMESTAMP` 读取为数据库文本后再解析为本地日期时间，避免容器 UTC 默认时区导致幂等重放回执偏移八小时。跨 MySQL/H2 时间文本解析由共享 MyBatis 行值转换器覆盖。

知识正文、来源元数据、审批状态和导入幂等请求存入数据库。同键同内容重放、同键异内容冲突。所有知识写事务先锁`knowledge_catalog_revision`版本行；审批/撤回同时追加冻结正文和哈希的`knowledge_approval_event`，不改写历史。待审稿只更新目录版本，审批/撤回另更新发布版本。各实例入口读穿版本、校验完整快照后替换本地缓存，读取失败不沿用旧批准缓存。

`KnowledgePublicationService`使用`knowledge_release`冻结正文/审批事件，远端构建及全量身份检查在事务外，短事务按目录→发布指针顺序加锁、重验授权并CAS切换`knowledge_release_pointer`。首次显式发布前保留LEGACY_UNPUBLISHED审批直读，之后仅活动快照参与检索；新审批须再次发布。撤回立即过滤，重新审批不复活旧事件。回滚仍须当前授权和索引核验，失败不切指针；检索结束前同时核验目录发布版本和指针。物理索引可被共享和重建，不是ES/Qdrant/MySQL分布式事务，检查后故障仍可能发生。管理员保留活动/最近三个READY/七日内快照，显式清理只删其他发布记录，不删正文/审批历史/共享索引。推送通知与自动清理未实现，详见[RAG](RAG.md#审批历史与版本化发布)。

升级须先停旧版知识写入实例，新增版本表后统一更新；混跑旧写手、绕过存储适配器直接改SQL、读取滞后副本不在此一致性保证内。已保存历史回答不追溯删除；最终检查与后续生成之间仍非跨系统原子事务，不宣称取消已发出的供应商请求。版本回退或快照非法会拒绝使用，而非悄悄降级。该方案每次入口读版本，完整加载仅发生在版本变化时，尚无容量/延迟结论。

问答轮次保存在 `triage_turn`，含请求标识、正文精确哈希、患者/助手消息关联和处理期限。`(session_id,request_id)` 唯一约束与会话行锁控制并发登记；同键同内容的已完成请求只返回当前会话，不重新生成，相同键换内容返回409。旧客户端不传requestId时由服务端生成，仅保留串行保护，不能保证客户端重试幂等。

模型调用在数据库事务外。最终回答、分诊版本、会话状态与轮次COMPLETED在短事务中一起保存；提交前验证RUNNING归属和数据库时间期限。默认处理期限180秒，可用 `AI_TRIAGE_TURN_LEASE_SECONDS` 在30～900秒内调整。过期任务不能写回旧结果；打开会话、查询轮次或登记下一轮时，将过期RUNNING标为INTERRUPTED并退出处理中，不自动重新请求模型。旧无轮次账本的处理中记录保留消息并转为待重试；升级前须停掉所有旧版实例，不支持新旧版本混跑。期限检查不保证取消已发出的供应商请求。

模拟预约在数据库事务内先以 `sim_booking_request(patient_id,idempotency_key)` 唯一键占位，再以条件更新扣号，最后写入带同键唯一约束的回执；任一步失败整笔回滚。并发同键请求在唯一键处竞争，败方事务退出后只读已提交回执：同医生/会话重放原回执，不同目标返回冲突，不再二次扣号。会话预约重新核验当前分诊状态、资料依据、风险和推荐医生；独立预约显式使用 `walk-in`，缺失会话不自动降级为独立预约。该实现只覆盖本应用数据库内的模拟号源，不提供真实 HIS 的跨系统原子性。

新预约回执时间统一为秒，与现有 MySQL `TIMESTAMP` 列精度一致；历史回执保留原快照。前端同页面的相同预约手动重试复用请求键，失败后提示先核对就诊记录；刷新后内存请求键不保留。真实 HIS 锁号、取消、对账与跨系统故障恢复尚未实现。

目录只展示启用且排班未过期的医生。服务状态分别表达科室不存在、停用、无医生、无匹配排班和无号源；启动不会自动续期历史排班或重置号源。多科室建议分别查询目录，单个查询失败不等于科室不存在。

## 生成侧安全边界

以下检查用于限制输出，不代表医学正确性已经得到证明：

| 边界 | 实现位置 |
| --- | --- |
| 风险与预约结构由后端决定 | `triage/domain/TriageSafetyPolicy`、`Disposition`、`booking/application/BookingApplicationService` |
| 资料依据状态与 `EVIDENCE_BLOCKED` | `triage/infrastructure/llm/OptionalNarrationModel`、`AnswerDraftValidator` |
| 召回/选留阈值与依赖故障 | `knowledge/infrastructure/qdrant/HybridKnowledgeCatalog` |
| `UNSAFE_OUTPUT` 检查 | `triage/infrastructure/llm/OptionalNarrationModel` |
| 药品句过滤 | `triage/infrastructure/llm/OptionalNarrationModel` |
| `SAFETY_RULE` 不受模型覆盖 | `triage/infrastructure/demo/RuleBasedTriageEngine`、`triage/application/TriageConversationService` |

患者输入和检索资料作为不可信内容注入提示。结构化回答检查本轮引用身份，`AnswerSupportReviewer` 通过一次独立模型请求核对内容支持；默认另要求逐断言完整覆盖段落、已采用引用ID及逐字来源原句绑定，缺项或不支持则降级。代码不证明医学蕴含，阶段/条件仍依赖模型判断。引用合法、核对通过与临床审核是不同事项；安全规则与中文映射未经临床审核，未命中不能排除急症。

## 可观测与权限

### 已知安全识别边界

以下是 `SafetyCoverageBoundaryTest` 固定的代码观察，不是临床期望标签或准确率；修复能力后应同步更新记录，不能为了保留测试而保留缺口。

| 输入类型与示例 | 当前确定性规则行为 | 边界 |
| --- | --- | --- |
| 比喻：“胸口像被大象踩了一脚，还冒冷汗” | 未产生信号 | 未覆盖该非标准表达，不能据此排除急症 |
| 俗称/压迫感：“胸口像压着一块石头，还冒冷汗” | 未产生信号 | 未列入胸痛模式词表，不能据此排除急症 |
| 明确否定：“我没有胸痛” | 当前被紧邻否定保护抑制 | 仅记录该样例的当前行为，不代表覆盖所有否定结构 |
| 第三人：“我朋友胸痛” | 命中胸痛规则 | 通用规则尚未隔离主体；过敏派生规则的局部主体保护不能代表全局事件归属 |
| 假设问句：“如果出现胸痛怎么办” | 命中胸痛规则 | 关键词安全检查先于模型意图，不区分这类假设咨询 |
| “去年胸痛”对比“去年发生过这些症状，胸痛” | 前者被历史前缀抑制，后者命中胸痛规则 | 有界前缀不是跨句事件记忆，不能保证时间归属正确 |

逐规则肯定/否定回归见 `Step1NegationGuardTest`，本表样例观察见 `SafetyCoverageBoundaryTest`，过敏无皮疹组合及局部历史/主体测试见 `AllergyAirwayCombinationTest`，模板分支与词表/出处缺口见 `SafetyRuleTemplateExpansionTest`、`SafetyRuleCatalogTest`。这批只增加边界记录，没有增加临床映射、修改严重程度或使用模型覆盖规则；POLICY_VERSION不变。独立医学审核和总体漏检/误报率仍未知。

### 受控只读 Agent（可选普通咨询分支）

`IntentExtraction` 和 `intent-extraction.schema.json` 定义意图、症状事件、主体、时间、否定、缺失信息与冲突。`IntentInput` 保留最近最多五轮完整消息、累计不超过4000字符；`IntentValidator` 拒绝额外字段、非法类型、重复键、非患者来源和不能在引用原话中找到的症状字段。它只验证结构与来源一致性，不能证明模型正确理解否定、主体或医学含义。

`AgentToolGateway` 仅允许医学检索、科室与排班三类只读工具，严格解析参数；身份、会话、trace、状态版本、语料版本及科室白名单由服务端运行范围提供，不能由工具参数覆盖。医学查询只接受本轮原话或经来源校验的本人/当前/肯定症状原词。`AgentToolRun` 限制调用数、单工具和总时限，按参数去重并阻止同一call ID改换参数；网关使用有界线程池、限制结果大小并传递trace。取消为尽力而为，不保证底层外部请求立即终止。

应用日常配置默认真实模型、Agent ENABLED、后端8081、前端5188及代理8081，rerank默认关闭；无需日常切换profile或VM参数。模型地址、密钥和数据库凭据从运行环境一次配置，不写入仓库。缺少密钥或模型地址时启动失败，不静默转demo；测试资源单独配置demo和Agent OFF，无AI环境变量也能测试。显式环境变量/VM参数仍优先于默认配置。

`AgentWorkflowSettings` 支持OFF回退和SHADOW影子抽取；SHADOW在普通咨询入口记录抽取状态，不改变回答。ENABLED由 `LangChainAgentModel` 使用 LangChain4j 工具请求/结果消息与兼容HTTP的 `tools/tool_calls/tool_call_id` 协议，交给 `AgentRunner` 有界执行。最多3次模型规划、4次只读执行；单次规划12秒、循环总预算25秒，均可向下配置。该预算不含抽取、最终生成及核对，不是全轮延迟承诺。结果上限12000字符，整个规划请求消息与工具定义上限30000字符；首次规划输出预算2048 tokens，工具结果后的结束轮64 tokens。不保存思考链或转发规划模型的自由文本。

`AgentWorkflowCoordinator` 在每步前后检查当前患者会话归属、消息数量与末条USER ID、启用科室及READY语料正文/版本指纹；知识读取现有数据库版本刷新，但会话/目录/工具执行之间仍非跨实例原子快照。仅真正执行成功的检索快照可传给原回答链，必须完成医学检索才接受模型的DONE；无证据不变成有证据。科室和排班结果只作为规划上下文，不授权预约或直接生成服务承诺。超时、工具失败、越权、重复循环、状态漂移均回退原工作流。急症/人工复核、受限请求在规划前退出，分诊评估和预约分支保持原路径。

`LangChainIntentExtractor`复用模型配置，发送来源消息JSON/Schema；demo/OFF/缺配置不外发，格式/来源失败不产生提案，不自动重试。抽取/规划状态、usage和耗时落库；合法观察在轮次完成后可见。`IntentRouting`支持复合类型、人工指引与有限历史追问，`TaskAwareQuery`只补当前原句任务词；不新增医学症状，也不扩大外发窗口。模拟预约PendingAction负责准备/确认/取消/过期与版本校验，模型无写权限。来源、路由及HTTP单测不证明意图语义正确或质量提高；新版本同配置质量复验尚需独立记录。

`TurnTraceContext` 为一轮处理分配 trace ID，消息来源、工具、生成、核对与终态日志通过 `agent_call_trace` 关联。上下文在 `finally` 释放，旧记录缺字段保留未知，不补造。生成与核对分别记录供应商返回用量；缺失用量显示未知，总耗时不能与子阶段耗时相加。这是本应用的逐轮关联，尚非分布式追踪，进程崩溃时仍可能缺日志。

`InvocationContext` 记录服务端入口决定的调用发起方：患者工作流WORKFLOW、模型只读规划及网关worker为AGENT、管理员试运行与旧HTTP工具facade为ADMIN、JSON-RPC MCP子集入口为MCP。它只是审计分类，不授予权限，也不接受模型或用户参数覆盖。上下文嵌套关闭时还原，线程不隐式继承，Agent工作线程显式建立来源。调用的`initiator`通过`agent_call_context`与日志同事务保存；患者每轮工具执行项也保留来源。旧数据没有来源时为UNKNOWN，不按用途/URL猜测；模型选择工具仍由后端执行，MCP标记不证明完整协议互操作。

`agent_call_usage` 与调用及trace同事务保存用量来源：PROVIDER_REPORTED保留供应商返回值（包括真实0，某侧缺失仍为null）；NOT_REPORTED表示未取得用量，不计算成0；NOT_APPLICABLE用于没有模型请求的本地操作；LEGACY_RECORDED保留旧正数及其未知来源，旧0仍未知。保留旧整数列供旧写手兼容，不回填历史用量，也不把Token数换算成供应商账单。管理员技术投影逐条显示来源，不暴露患者或工具入参；损坏/非法来源元数据显式报错而非伪造零。

普通管理员通过 `TechnicalCallView` 查看脱敏技术投影；人工队列不直接返回患者正文。摘要还需 `HUMAN_REVIEW_AUTHORIZED_SUBJECTS` 显式授权，读取与拒绝访问落库，读取审计失败时不返回正文。没有批量导出或自动清理策略。

演示 JWT 可通过 `AI_JWT_SECRET` 配置稳定密钥；未配置时进程启动随机生成，重启令牌失效。关闭演示登录不会自动接入医院 SSO。

## 前端恢复与交互

可选全栈容器由 `compose.app.yml` 合并基础依赖；前后端多阶段构建，Nginx代理API并禁用SSE缓冲。演示认证默认仍禁止非回环绑定；只有显式 `AI_DEMO_LOCAL_CONTAINER=true` 且存在Docker标记时，允许容器内部0.0.0.0。宿主机端口必须保持127.0.0.1，应用无法验证外层映射或反向代理，开关不是公网部署许可。日常IDEA无需该开关。镜像健康检查只检查进程，数据库就绪单独查询；restart策略不等于不健康自动重启或OOM恢复验证。

`/api/health/live` 仅返回进程UP，不调用数据库、模型或检索供应商；`/api/health/ready` 验证并释放数据库连接，失败仅返回503/DOWN，不公开连接信息或异常正文。它们不表示知识、模型、检索或医学功能可用；外部供应商短时故障不作为进程重启依据。

管理员壳层只负责认证与导航，各业务页面自行加载数据，不在每次进入后台时预取七类无关资源。工具中心使用独立加载、持久可见的错误与显式刷新；试运行展示本次实际返回数据，不使用短暂 toast 代替结果。启停请求结果不确定时不自动重发，先刷新后台状态再开放操作。管理员试运行是直接调用本地执行器，不代表模型选工具或完整 MCP 调用。

科室/医生目录首次加载只读取一组快照；加载失败可显式刷新。写入成功与后续刷新分别处理：保存成功但回读失败仍保留成功提示，要求刷新核对后继续编辑；写入响应丢失时显示结果待核对，不自动重发或允许连续提交。

退出登录会清除请求模块内存 token 和本应用登录缓存，保留同源其他存储项。请求与演示 token 刷新绑定本次登录状态：退出或切换登录后，旧请求、旧刷新结果和阶段流结果不再交给页面，也不会恢复旧账号 token。该限制不撤销服务端已经受理的业务操作或替代后端鉴权。

人工导诊申请页串行处理列表刷新、摘要读取和状态修改。列表未确认时禁用旧行操作；修改结果不确定时清除已展开摘要，要求刷新核对后才能继续，不自动重发。状态修改成功也清除旧摘要，后续查看重新经过服务端授权与读取，避免沿用旧医疗内容。前端操作限制不代替后端权限和状态迁移检查。

SSE推送阶段状态和保存后`answer_delta`分段（消息ID、连续序号、checked）；每段最多32码点，无打字机定时器，最终result与拼接答案必须一致。供应商SSE在服务器256KiB及总时限内完整缓存、解析和核对，未核对草稿不外泄；不是供应商逐token直推，不减少首段等待。异常只转固定失败事件，不回显内部详情。断流后按requestId/消息ID有界回读保存结果，`GET /api/triage/sessions/{id}/turns/{requestId}`仅本人可查，没有事件队列或Last-Event-ID补发。sessionStorage只存未确认UUID/内容哈希，完成/终态/退出时清理，不保存医疗原文；存储不可用则不能保证跨刷新身份。运行中及危险状态不普通重发，失败/中断需用户新建轮次，不自动重跑模型或预约。

`TriageStreamDisconnectTest` 使用随机回环端口、真实HTTP与应用数据库写入：收到ACCEPTED后阻塞测试服务入口，确认同会话重复请求409，关闭客户端响应体后放行原请求，按requestId回读COMPLETED及唯一消息对，并验证同键重放和异内容冲突。夹具只暂停执行时机，不伪造回答或保存结果；使用H2和固定合规回复，不调用外部模型，不代替MySQL跨进程恢复、真实模型或浏览器断流验收。

会话切换和资源刷新只应用当前版本的响应；单个资源失败保留其他成功结果。患者资料成功读取版本后才能编辑，版本冲突保留修改并要求显式重载。历史分诊、采用来源与用时读取保存快照，不由当前目录或新资料覆盖。

详细检索设计见 [RAG](RAG.md)，启动与验证见 [README](../README.md)。

容器前端将原始 Host（含访问端口）转发给后端，保证配置了非默认端口时同源校验仍正确；不因此扩大后端跨域白名单。独立外部 Origin 的请求仍受原 CORS 策略约束。
