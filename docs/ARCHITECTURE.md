# 项目架构

Spring Boot 单体按业务模块组织 api、application、domain、infrastructure；当前不是完整 DDD、微服务或多 Agent 编排。

## 模块

| 模块 | 职责 |
| --- | --- |
| identity | 演示登录 |
| triage | 多轮会话、危险信号、分诊版本、模型回答、人工导诊 |
| booking | 模拟预约、资格校验、幂等与原子扣号 |
| catalog | 科室、医生、模拟号源 |
| knowledge | 资料、BM25、Qdrant、融合与重排 |
| tools | 本地工具执行器与 MCP 子集入口 |
| observation | 统计与调用记录 |
| shared | API 契约、身份校验、异常和公共基础设施 |

依赖方向为 api → application → domain 接口，infrastructure 提供数据库与外部服务实现。仍有共享契约和跨模块直接依赖，不宣称完全隔离。

## 改造验收顺序与未完成项

后续以完整患者闭环验收，不以单次模型回答或小样本召回通过宣告完成：先验证运行版本并收拢未提交源码，再补最小逐轮路由/检索/生成/核对/失败诊断及敏感访问授权，复核旧语料正文、来源和适用范围，完成咨询到分诊、模拟预约或人工导诊的端到端评估，最后基于耗时数据优化性能及后台索引发布。上述仍为待完成项，不是现有功能声明。

一般追问不按每种症状增加Java分支；安全与预约权限由后端约束，模型承担自然回答和按需追问。无资料、无科室、无号源、检索故障和模型失败分别呈现；历史结果保留快照。召回相关性、引用完整性或模型核对均不能证明临床正确。完整任务清单保留在本机协作方案，不将每轮工作记录公开上传。

## 请求流程

会话服务读取当前消息与有界历史，执行风险和流程判断。危险信号由安全规则接管；普通路径显式查询知识、科室与号源，再调用模型。检索无结果时可以进入一般问答路径，不能据此生成缺乏依据的具体分诊结论。历史分诊版本保留快照。

患者流程调用进程内工具执行器，没有模型自主选择工具的循环。管理员认证的 /mcp 共用执行器，提供列表与调用子集。

## 数据一致性

MyBatis Mapper 执行 SQL，默认 H2；MySQL profile 的真实联调尚未完成。模拟预约在事务中以条件更新扣号，并使用幂等键防重复创建。前端展示的号源不等于锁号，后端须再次核验预约资格。

预约输入必须包含有效医生、会话标识和幂等键；缺失会话不得自动转换为独立预约，独立模拟预约显式使用 `walk-in`。应用入口委托同一事务服务：先返回相同患者、相同请求的成功回执，不重新扣号；新预约再校验当前资格。复用键但改变医生或会话返回冲突。

新预约回执时间统一为微秒，避免首次内存返回与SQL时间戳回读精度不同；集成测试核对完整回执，而不仅是预约ID。历史预约不重写。

前端同一页面内的相同医生、日期、时段、会话手动重试复用请求键，成功后释放；失败不自动重发，也不断言后台未保存。刷新页面后该内存键不保留，患者须先查看已有回执；这不是跨页面或跨设备的重复预约限制。

患者医生、预约、会话和时间线分别加载，单个失败不丢弃其他成功数据。失败资源持续显示未知/未刷新及只读重载入口；预约和就诊页面不会把对应资源失败展示成空记录。重叠刷新只应用最近一批结果，恢复读取不重发问诊或预约。

本人资料必须成功读取当前版本后才能编辑保存；首次读取故障不呈现空白可提交表单。版本冲突保留本页修改并阻止继续保存，用户显式重载时才放弃本页修改；资料始终是患者自述而非医院核验。

历史会话读取按当前选择版本应用；切换、新会话或发送会使旧读取失效，旧响应及旧错误不能覆盖当前窗口。人工导诊异步回执只更新同一会话，不写入随后打开的另一会话。

`node scripts/test-booking-input-live.cjs` 在本机8081使用演示李四身份检查五类非法标识及预约/目录前后快照；只提交应被拒绝的请求，不创建预约或调用模型。它不代替真实HIS、并发事务或临床验收。

目录仅展示启用且排班日期未过期的医生。启动不会把管理员已保存的历史排班自动滚动到未来或重置号源；管理员应维护有效排班。探针遇到空目录仍验证非法输入及预约不变，但将号源变化记录为未知，不冒称完成扣号验收。

会话预约仅接受当前“已完成分诊”的会话、已取得资料依据且风险为“普通”或“多科室参考”的结果，并再次核对推荐医生。未知风险、处理中、待重试、待补充及危险提示状态不得借历史结果扣号；历史快照仍可查看。独立模拟预约入口和已成功幂等回执不因此改变。这些校验不等于跨实例会话/预约串行化，真实医院接入仍需事务边界与身份制度联调。

同一进程的会话服务为JSON和SSE处理共用会话进行中闸门，重复处理在追加患者消息前拒绝，结束或异常后释放。SSE入口另保留即时重复提交检查。该闸门不是跨实例分布式锁；预约原子扣号和幂等约束仍由数据库承担。

患者端同时读取本地发送状态和持久化会话状态：刷新后仍“处理中”时禁止重发，可只读刷新结果；“紧急提示”停止普通问诊。回答已经保存后，侧栏列表刷新失败仅提示列表未刷新，不恢复输入或重发本轮问题。

多科室分诊对主科室及每个不同候选科室分别查询目录能力，结果保存工具轨迹；明确预约或未拒绝预约的方向咨询，附加后台生成的逐科室服务提示。结构化回答路径不把服务提示发送给生成模型，也不当作医学证据。一个方向可用不能证明另一方向有号源；单个查询失败标记QUERY_FAILED，不冒称科室不存在。医学依据、目录状态和预约资格仍是不同边界，急症路径不查询目录。

患者分诊卡片从所选版本的结果快照读取全部科室服务提示，不读取当前目录覆盖历史。模型超时或依据核对拒绝时仍可显示已取得的后台查询事实，但不能因此解除预约闸门；旧记录缺提示时不补造其他科室状态。

本人资料与聊天记录不是正式病历。没有医生工作台、真实 HIS 或医院实时人工值守。

知识正文、审批状态与来源元数据通过 KnowledgeDocumentStore 端口及 MyBatis 实现保存。检索缓存从数据库重建；新增失败回滚缓存，审批写入成功后才发布。结构化资料的许可声明未解决时不能发布；声明不是临床或法律认证。MarkdownChunker 生成章节与位置溯源，BM25和Qdrant共享批准正文；Qdrant召回校验point id与payload是否符合请求快照，不证明医学适用性。

## 生成与安全边界

2026-10-07权限边界：普通ADMIN调用观测接口通过TechnicalCallView白名单投影，不返回患者身份、工具原文或原始错误。人工导诊队列及状态更新仅返回申请编号、状态、时间和摘要访问资格，不返回患者身份、申请原因或会话编号。摘要读取另需review.authorized-subjects（环境变量HUMAN_REVIEW_AUTHORIZED_SUBJECTS）明确授予现有ADMIN认证subject；默认空列表拒绝所有摘要读取，无通配授权。授权绑定令牌subject而非显示登录输入；该部署配置不是医疗人员资质认证。读取和已认证ADMIN的拒绝访问记录写入review_access_audit，读取审计失败时不返回正文。未开放批量导出，未制定自动清理期限；不是全系统隐私合规已完成。

AnswerCallAudit将本轮回答diagnostics.traceId关联为调用ID，生成与回答核对分别记录供应商实际返回用量，核对记录ID为同trace加-review。缺失用量保持旧存储占位0，技术接口显示未知，不估算、不把部分已知用量合并成完整总量。模型失败、输出拦截或工具失败不再记作回答成功。主流程elapsed含检索及核对总等待，核对行是子阶段耗时，不能相加当完整总耗时；尚不是所有路由、工具和消息关联齐全的逐轮trace。概览工具调用数按数据库实际四类工具执行记录计数，含失败，不再用日志数乘4估算。

脱敏calls接口在原8081经HTTP验证：未认证401、患者403、管理员200，200条现有记录无敏感字段。此前提交源码JDK17、无AI_*、隔离clean test共298项（297通过、1外部跳过），前端build通过；覆盖测量用量、核对独立记录、失败终态、真实工具计数、普通管理员脱敏、显式摘要授权与审计失败不返回正文。随后重启真实复验通过；新逐轮关联补丁需另行加载，不将作者测试称独立复核。

- TriageSafetyPolicy 评估危险信号，模型不能解除风险和预约闸门。
- BM25/Qdrant 阈值、RRF 和 rerank 筛选片段，相关性不代表医学适用性。
- 模型提示词把患者输入与资料声明为不可信数据。
- 输出检查拦截部分不安全表达与用药指导，不保证医学正确。
- 紧急 SAFETY_RULE 路径不等待模型，预约服务再次核验限制。
- SSE 推送处理阶段；正文完成检查后一次返回，尚非逐 token 输出。
- 状态连接中断后，患者端最多回读20次（间隔1.5秒）核对该次已保存问题及结果，不重发问诊或预约。仍处理则提示稍后查看；结果已保存则恢复显示。回读次数有界，网络请求本身仍受浏览器连接行为影响，不承诺严格30秒结束。

规则与中文映射未经临床审核，未命中不能排除急症。外部调用故障必须与无资料区分，降级不能标成模型调用成功。

演示JWT由进程内签名服务签发；配置 `AI_JWT_SECRET` 时密钥需至少32字节且跨重启/实例保持一致。未配置时每次启动生成随机密钥，令牌重启后失效。应用没有医院OIDC/SSO适配器；关闭演示认证只关闭演示入口，不会创建真实登录能力。医院接入前须另做认证和角色映射。

显式运行 `node scripts/test-triage-audit-live.cjs` 可在原8081验证技术投影、人工导诊队列与真实回答审计关联；会创建一条合成李四会话，不预约、不修改目录。要求后端真实模型已配置；真实回答或核对失败会退出非零，不以审计正确掩盖回答失败。该脚本不是默认离线测试，也不是临床质量验收。
