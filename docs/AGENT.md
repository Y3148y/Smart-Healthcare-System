# Agent 与工作流

## 业务边界

回答的已保存执行链可包含`ROUTE`技术事件：工作流记录原有路由及原因（危险信号优先、人工复核、信息补充、可进入评估），不保存用于判定的患者原文。患者折叠明细按已有事件解释；旧记录没有事件时不反推原因。该事件只说明现有确定性流程的选择，不是新意图路由、医学诊断、模型决策或预约许可。

`scripts/test-observation-trace-ui.cjs` 在随机本机端口加载实际Vue观察回看、执行明细与管理员观测组件，用真实Chromium验证懒加载、历史标签、原话仅文本、切会话清理、限高、失败重试和同轮链路失败清理。所有API由浏览器拦截为合成GET，其他API/外网请求使测试失败；不需要后端或模型，不能用作后端鉴权/数据库/真实模型验收。依赖已安装的前端包、`NODE_PATH`中的Playwright与Chrome；可用`ADMIN_TEST_BROWSER`指定Chromium。测试自己关闭浏览器和临时服务，现有8081/5188不受影响。CI已配置该入口，实际远端运行须另查记录。

旧的多科室方向提议由 `StructuredDecisionModel` 执行，与只读Agent规划不是同一次请求。它现在同样只发送最近完整5轮/4000字符、允许的科室名字，不发送累计症状全文或候选理由中的窗口外内容；名单作为不可信数据，不进入系统指令。单次和本轮累计输入预算都在SDK客户端构造前检查。必须显式配置base URL，不回落到SDK默认供应商；非STOP返回不能凭一段完整JSON当作成功。供应商用量、已知本地未请求、旧适配器未知分开审计，错误仅记录固定码和类型，不记录异常正文。原科室白名单、风险规则与被拒绝后的规则回退不变；限窗与日志修复不代表方向选择质量提高。

管理员“AI运行观测”的“查看本轮链路”沿用受ADMIN认证保护的 `/api/admin/calls?traceId=...`，按同一轮次关联已保存的抽取、规划、生成、核对和工具记录。最多200条，按记录时间显示，不保证完整阶段或严格因果顺序；失败、缺用量与本地调用的含义不变。不暴露患者原话、工具参数或供应商原始错误；切换轮次/刷新/离开页面会使在途旧结果失效，避免旧请求覆盖当前视图。该入口不额外调用模型，不是分布式链路平台。

调用列表与同轮链路在模板消费前校验技术记录及嵌套工具结构；异常响应、重复记录或非法用量拒绝显示，不伪装为空列表或0 Token。配置/记录读取失败采用固定说明，不回显服务端原始错误正文；旧记录缺少可选用量来源/发起方仍显示未知。

患者普通咨询使用一个受控只读 Agent，不是五个诊疗 Agent，也不是 MCP 客户端。安全规则、分诊结果保存和预约资格由后端控制。未接入真实 HIS，未完成临床审核。

## 代码职责

| 组件 | 职责 | 不负责 |
| --- | --- | --- |
| `TriageConversationService` | 身份、同会话并发保护、消息/分诊保存、会话状态 | 模型工具循环 |
| `TriageWorkflow` | 协调路由、普通咨询和分诊计算，返回类型化结果 | 数据库写入、预约提交 |
| `WorkflowRouter` | 复用原安全与追问策略，返回 `RouteDecision` | 新增医学词表、模型风险裁决 |
| `LangChainIntentExtractor` / `IntentValidator` | 意图抽取、Schema和患者原话来源校验 | 证明医学语义正确 |
| `SessionFactReducer` / `SessionFacts` | 来源验证、追加归并和保守检索投影 | 自动消解事件、清除原文风险 |
| `AgentWorkflowCoordinator` | 冻结工具作用域、检查新鲜度、采用实际检索快照，并把成功的科室/排班查询压成不含医生身份的服务状态 | 采用规划器自由文本作为答案或把服务状态当医学依据 |
| `AgentRunner` / `AgentToolGateway` | 有界工具循环、严格参数、权限范围、预算和去重 | 写预约、审批知识 |
| `GuidanceAnswerService` | 普通咨询检索、复用准备好的证据、调用原回答与审核链 | 固定安全回复和合规裁定 |
| `RuleBasedTriageEngine` | 既有安全/追问策略、候选方向、分诊计算 | 事实持久化、模型自主预约 |

没有为了目录整齐重建所有业务模块。预约、知识、目录等继续按业务模块分层；现有引擎仍有历史策略与兜底文案，本次未假称完全解耦。

检索投影按同一消息内的原话引用定位冲突：引用相互包含时关联到对应观察，只阻止相关症状/主体/时间组合进入Agent查询白名单，其他来源明确的症状可以继续检索。整句冲突引用可能同时关联多项观察；无法关联任何观察的冲突仍阻断全部症状查询。观察和冲突均追加保留，代码不推断同义词、事件是否同一次发作或冲突已经解决；安全规则与预约权限继续走既有工作流。

## 一轮执行

```text
身份和输入校验 → 保存患者消息 → TriageWorkflow / WorkflowRouter
  ├─ 急症或人工复核 → 原分诊安全路径，不进入Agent
  ├─ 需要咨询或补充 → Agent可选准备医学证据及只读服务状态 → GuidanceAnswerService
  │                   → 原生成/引用检查/支持核对
  └─ 可进行评估 → 原分诊引擎
最后由会话服务保存回答、来源、状态和分诊版本。
```

路由判断顺序保持“立即就医 → 人工复核 → 是否需要补充 → 评估”。`RouteDecision` 是工作流分支，不是诊断或预约凭证。固定拒答和出血追问仍由原安全/合规策略产生，不交给模型改写。

## 事实归并

患者可按需展开“会话观察记录（非病历）”，调用仅限PATIENT且由存储层核验本人归属的 `/api/triage/sessions/{id}/observations`。只读取已完成轮次快照，暂存/失败轮次不可见；无快照或无观察不表示没有症状。历史CURRENT显示为“当轮标记为当前”，保留主体、肯否、原话与待核对冲突，不推断现在仍成立，也不覆盖安全规则。返回sessionId与前端选中会话绑定，切换/关闭/卸载使旧请求失效；默认折叠、按需读取、限高滚动，不占用固定对话覆盖层。它是本系统保存的AI观察回看，不是病历、诊断或完整事件消歧；展开不调用模型，不将窗口外记录发给百炼，也不将患者数据写入本地存储或公开仓库。

- `SessionFactReducer.merge` 接收带版本的旧投影和经校验的提案；新增来源必须来自当前输入中的USER消息，不能来自助手。
- 精确重复事件去重；新的否定不删除早先肯定事件。版本倒退或同版本改变事实会拒绝。
- 本人/他人、当前/既往/未知、肯定/否定/不确定保持分离，不猜测事件身份或临床同义词。
- 派生查询只采用本人、当前、肯定症状原词；同词同主体同时间分类有否定/不确定观察时不生成该词。提案有显式冲突时不生成任何派生症状词，仍可使用本轮完整原话检索。
- 当前工具输入仍只重建最近五轮/4000字符窗口的投影。来源校验后的观察另以版本化快照持久化，只有轮次完成后可见；它不是临床事实，也不自动将窗口外内容发送给模型。完整医学事件消歧和历史事实驱动追问尚未实现；来源校验不能证明模型正确理解了主体、时间和否定。
- 原安全检查继续读取患者原话累计历史，不消费此投影清除风险或赋予预约资格。

## 配置、失败与验证

### 离线意图与工具评分

`node tools/rag-eval/agent-quality-cli.mjs <run.json> <reviewed-labels.json>` 不联网、不调用模型，仅输出技术计数。运行文件 `schemaVersion:1` 包含 `dataset`（同版本、id、DEVELOPMENT/HOLDOUT、cases）、`configuration`（model、promptVersion、policyVersion）与 `results`。每个数据项保存id和input.messages（id/role/content，最多5轮/4000字符）；结果保存id、唯一traceId、inputSha256、COMPLETED/UNAVAILABLE/INVALID、intents、tools（name/success）、elapsedMs、可空inputTokens/outputTokens和tokenUsageSource。工具名仍限现有三个只读工具。指纹采用工具导出的 `agentFingerprint` 对排序键后的JSON作SHA-256，绑定输入、完整数据集和完整运行。

标签文件同版本，包含datasetSha256、runSha256、reviewer（id及AUTHOR_ENGINEERING/INDEPENDENT_ENGINEERING）与cases（id、期望intents、期望tools）。每项必须由评审者填写，不自动从模型答案生成；“独立”是评审者声明，程序不能认证其身份。原始输入与标签只留本机忽略目录，不提交患者内容。修改输入、Prompt版本、输出或配置后，旧标签不能复用。

输出意图/工具集合完全一致率、micro Precision/Recall/F1、缺运行/未标注/失败数、评审样本完成率、全部运行p50/p95和供应商声明用量覆盖数。重复查询同工具计多次执行，但工具选择集合只计一次；选择正确与执行成功分开。失败不变成“空集合正确”，也不悄悄消失，已有标签却缺运行的项目仍进入完成率分母；缺失用量不作0。空分母为null。此工具不自行判定症状同义等价性、临床正确或真实账单；目前测试是合成工程夹具，没有多场景实测质量成绩。

可选的逐项 `eventReview:{exhaustive:true,events:[...]}` 与运行结果中的 `events` 支持事件评分。事件沿用IntentExtraction字段，原文数据集消息id映射sourceRefs.messageId；最多20事件、每事件1–5条患者原话引用，助手文本或不能在引用找到的字段不能补证据。只有穷举事件标签参与评分；无标签/部分标签保留未知。按“症状原词+患者消息与原句引用”精确锚定，匹配后分别比较subject/temporality/assertion；事件完整字段集合另算Precision/Recall/F1，额外/遗漏事件不被归属正确率掩盖。重复且歧义的锚点须先由评审者解决，不猜配对；不同同义表达不自动算等价。它测的是显式工程标签一致性，不是程序自行裁定医学事实；当前仍无独立多场景实测成绩。

回答生成由 `ContextAssembler` 整条组装系统约束、引用资料和最近五轮对话（对话累计≤4000字符）。证据按完整引用JSON≤4000字符选择，保留原引用ID和哈希，不能截掉条件句；总预算不足时先移除最早完整对话轮，再移除末位完整证据。本轮问题和系统约束不可裁；无法容纳时明确 `CONTEXT_BLOCKED`，不是检索未命中或供应商故障。不得把所有证据裁掉后冒称无资料。

兼容的 `explainWithServices`、`guide`、`guideGeneral` 入口同样在创建模型客户端前组装和检查预算；本地预算阻断保留 `PROMPT_PREPARATION`、不记录供应商调用用量。兼容入口未取得版本化检索快照时，其检索状态为UNKNOWN，不猜测未命中。

`AI_CONTEXT_INPUT_TOKEN_BUDGET` 默认65536，允许512–262144。此处以UTF-8字节加消息开销作保守估算，**不是模型分词器、供应商实际Token或账单**，也不保证适配所有模型的上下文上限。回答核对请求在发送前独立检查同一预算，超限不请求供应商；阶段明细可查看估算和整条移除数量。意图抽取同样检查完整Schema和原话JSON，超限保留来源、不静默裁剪，返回固定`INTENT_CONTEXT_*`并回退工作流；这类本地阻断不计供应商请求用量。成功组装记录CONTEXT/INTENT_EXTRACTION估算，实际用量仍取供应商响应。

工具规划使用与发送端相同的消息序列化，计入系统消息、原话/意图、调用参数、工具完整结果和广告Schema；初轮及DONE续轮均检查，仍保留累计30000字符上限。超限`CONTEXT_*`回退、不发送、不截断结果或扩大授权窗口，审计为本地阻断。折叠明细区分意图抽取/工具规划/回答生成的估算。上述单次配置分别限制各阶段输入；另有下述本轮累计输入估算限制，两者均不是供应商账单；步数、工具次数、超时等既有门禁仍独立执行。

`AI_TURN_INPUT_ESTIMATE_BUDGET` 默认262144、允许512–1048576，为活动患者轮次增加跨抽取、各次规划、生成、核对的累计输入估算预占。明确恢复trace的工作线程共享同一原子预占列表；后续调用不能提高本轮已采用的上限。超限在发送前固定`CONTEXT_TURN_INPUT_BUDGET_EXCEEDED`（抽取/核对带各自前缀），跟踪容量不足另报`CONTEXT_TURN_TRACKING_UNAVAILABLE`，不伪装成额度耗尽或供应商故障。预占不因输出校验失败或超时退款，以免未知供应商状态被当作未收费。明细展示累计预占与剩余估算，不当作实际消耗。

此限制只覆盖同一进程内活动trace的上述对话模型输入，不是持久化/跨实例月度配额，不包含Embedding、rerank或输出Token费用。无活动trace的独立兼容调用仍仅执行单次预算，不声称有本轮累计控制；重新运行的新轮次重新计数。输出上限、工具步数、超时、医学与预约门禁仍独立存在，累计预算阻断不会覆盖急症结论。窗口外患者观察依旧不外发。

日常主配置启用真实模型及Agent，OFF回退、SHADOW影子抽取均可显式选择。默认最多3次规划、4次只读执行、单次规划12秒、规划循环25秒；这不是全轮延迟承诺。状态/语料/目录漂移、非法调用、超时、循环或模型失败时回退原工作流。

抽取和只读工具规划默认分别使用不输出思考链的短请求；患者回答生成仍按 `ai.enable-thinking` 配置。两阶段可分别用 `AI_INTENT_ENABLE_THINKING`、`AI_AGENT_PLANNING_ENABLE_THINKING` 调整。这个配置只控制供应商请求，不改变引用、风险或预约检查。原8081实测意图抽取在8秒截止，故不能以普通回答成功冒充Agent完成。

只读工具的本轮参数Schema列出服务端批准的查询与可用科室，减少模型提出无权使用的参数；症状事件存在时，只允许来源校验后的本人、当前、肯定症状原词，原始混合句不会成为绕过肯否/主体/时间判断的额外查询。只有未抽取到症状事件的一般健康知识问题才可保留当前原问题。空医学查询白名单会拒绝所有Agent医学检索；`AgentToolGateway`逐项验证实际参数。越界参数记为`TOOL_BLOCKED`并回退，执行器故障记为`TOOL_FAILED`。两者都不授权预约或医学风险结论。

Agent 若成功查询科室或模拟排班，回答链复用同一轮快照并将其简化为患者可见的服务状态提示；仅传科室名、状态和号源数量，不传医生姓名。服务状态不会作为医学证据，也不授予预约资格；未查询到的服务继续显示未查询，查询失败不改写成“没有科室”。医学检索query为空时，回答链跳过医学RAG与最终回答模型，固定提示患者补充健康问题，并把已取得的目录结果单独展示；Agent的工具白名单也会在无合法医学检索词时移除医学检索。`retrievalStatus=NOT_APPLICABLE`表示本轮没有医学查询，不是检索未命中；前置意图抽取/工具规划仍可能调用LLM。非空健康查询即使Agent没有预取结果，仍走既有RAG回答链。

意图抽取成功后，患者执行详情会显示受控意图枚举和本轮工具白名单（`INTENT_ROUTE`）；只记录例如`FIND_DOCTOR`和工具代码，不记录原话或提取出的症状字段。它解释模型为何可选某些只读工具，不代表模型已调用它们，也不改变安全分流、分诊或预约权限。

工具选择按已验证意图和当前请求收窄：一般咨询只暴露医学检索；明确找科室或医生时才暴露对应目录工具。一次成功的医学检索结果回传后，不再向下一轮模型提供同一检索工具；模型必须读取结果并返回`DONE`，否则回退。无待选工具时仍可传递既有工具结果。真实线上审计需出现`Agent执行/COMPLETED`才能称Agent完成；仅有模型返回`TOOLS`或最终回答`LIVE`不够。

兼容接口的续轮仍带上刚执行工具的函数定义，并以`tool_choice=none`禁止新增工具请求；服务端同时验证返回不能含`tool_calls`。规划失败只记录异常类型/HTTP状态映射出的固定失败码，不记录供应商错误正文或思考文本。

收到工具结果后的结束轮再加入明确的“仅返回DONE”控制消息，输出上限64 tokens；只有独立的`DONE`标记才算规划完成。其他停止文本记`INVALID/STOP_NON_DONE`，长度等非正常结束记固定`FINISH_*`码，不保存模型自由文本或把它作为患者回答；旧工作流仍可保守接管。该修正在百炼配置下通过一次合成普通咨询闭环复验，不能据此宣称多场景稳定或临床适用。

意图抽取失败通过现有异常分类器记录固定错误码，区分 `INTENT_MODEL_TIMEOUT`、`INTENT_MODEL_AUTH_FAILED`、`INTENT_MODEL_RATE_LIMITED` 和网络等错误；不记录供应商正文、异常消息或密钥，不自动重试。429只代表限流响应，不能单凭此码判断额度耗尽。抽取失败不进入工具规划，后续工作流生成的回答仍须独立通过引用与支持核对；工具成功或审计关联成功不代表答案通过。

模式回退不删除持久化观察或待确认预约。`AI_AGENT_MODE=OFF` 关闭后续抽取/规划入口，不会给旧动作增加权限：确认仍检查本人、期限、取消状态、会话版本与排班；已确认动作重放原回执，不重复扣号。模式配置在启动时读取，不是热切换。`AgentModeRollbackTest` 用两个无Web应用生命周期共享隔离H2数据，验证ENABLED准备、OFF恢复后的保留/拒绝/单扣及已完成观察读取；夹具直接构造合法观察与评估，不冒称真实模型、多进程或MySQL验证。跨JVM预约竞争另有专门集成测试。

测试入口：`WorkflowRouterTest`、`TriageWorkflowTest`、`SessionFactReducerTest`、`GuidanceAnswerServiceTest`、`AgentWorkflowCoordinatorTest`、`AgentRunnerTest`、`AgentModeRollbackTest` 和 `AgentFunctionCallingTransportTest`。完整运行方式为JDK17下 `cd backend; .\mvnw.cmd test`（Linux/macOS：`./mvnw test`），前端 `npm test` 与 `npm run build`。

本地HTTP协议测试只证明适配器消息传输。2026-10-11 在百炼配置下的一次合成普通咨询已观察到模型选工具、工具结果消费、`Agent执行/COMPLETED` 和独立回答核对 `PASSED`；这是单样本集成验证，不证明稳定性、临床准确性或性能收益。患者页面的服务端待确认预约动作已接入，但不是模型生成动作，Agent仍无预约写权限。来源校验后的模型观察可跨轮持久化，并仅在轮次完成后发布；历史观察不会自动进入当前工具/模型窗口。完整事件消歧、历史事实驱动追问、完整意图路由与多场景真实模型验收仍待完成。

## 可核验的五项能力表述

- 基于LangChain4j接入受控只读Agent与后端Workflow：模型在白名单内选工具，工作流控制安全分流、权限和模拟预约；规划与工具次数有上限，不是完整MCP Agent。
- 实现Schema约束的意图抽取、患者原话来源验证与完成轮次观察快照；区分主体、时间、肯否与未知，但未宣称语义归属准确率或完整事件消歧。
- 实现ES/Lucene BM25与Qdrant混合检索、RRF融合和可选重排，按获准片段与章节构造引用。禁用重排有独立路径，不用作者主题命中率冒充完整Recall/Precision。
- 实现分层上下文、完整消息/证据裁剪、输入估算预占、引用检查与第二次模型支持核对；生成后再复查来源成员。模型核对不是临床审核，来源检查不保证与保存原子化。
- 实现session/turn/trace关联、发起方和用量来源审计，以及绑定版本的离线评分工具。缺失用量和无独立标签保持未知，不宣称未测的延迟收益、忠实度或召回提升。
