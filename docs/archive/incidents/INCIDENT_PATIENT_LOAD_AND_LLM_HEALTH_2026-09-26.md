# 患者数据加载失败与 LLM 健康检查

日期：2026-09-26

## 现象

患者端预问诊页弹出“患者数据加载失败：请检查后端服务”。用户要求确认 LLM 是否真正调用，以及 API 是否健康。

## 复现与原因

- 当时 5188 前端和 8080 后端均在线；`/api/doctors` 通过代理返回 HTTP 200。
- 使用新登录获得的 Token，请求 `/api/doctors`、`/api/appointments`、`/api/triage/sessions` 全部返回 HTTP 200。
- 使用失效 Token，后两项返回 HTTP 401，而医生列表作为公开接口仍返回 200。
- 前端旧实现只要在本地存有演示 Token，就跳过新登录；三个接口使用 `Promise.all`，任意一个 401 都会合并成“患者数据加载失败”。提示中的“后端服务”因此不准确。

## 修复

1. 演示入口每次页面初始化时重新向后端认证，不再仅凭本地 Token 判断已认证。
2. 已打开的页面遇到受保护接口 401 时，自动刷新演示 Token 并重试原请求一次；并发 401 共用同一个刷新任务。
3. 接口错误消息保留 HTTP 状态，401 明确标注登录已失效。
4. 前端生产构建通过。

## 后续复测

- 补充了 `frontend/tests/api-auth-retry.cjs`，覆盖失效演示 Token 自动登录并重试、并发 401 先后到达时只刷新一次，以及普通登录页面不会偷偷改用演示账户。
- 修正并发边界：请求发出后若其他请求已更新 Token，直接用新 Token 重试，避免重复登录。
- 使用运行中的 5188 代理和 8080 后端，真实发送失效 Token：首次预约接口返回 401，前端调用演示登录接口，再用新 Token 重试成功；随后会话列表也读取成功。四项认证测试全部通过。
- 前端 `vue-tsc --noEmit && vite build` 通过；5188 页面和 8080 医生接口均返回 HTTP 200。

## LLM 健康实测

- 直接请求配置的 Qwen API，返回模型 `qwen3.7-flash-2026-07-15` 与“健康”，耗时约 3.9 秒；模型端点、密钥和模型名可用。
- 通过正在运行的 `http://127.0.0.1:5188/api` 完成患者登录、三项数据读取和真实分诊。
- 输入“我最近头晕想吐，请问该挂什么科？”时，后端返回神经内科、相关官方 RAG 来源，以及针对起病时间、持续时间和危险信号的自然语言回答。
- 该结果的 `modelStatus=LIVE`，`modelName=qwen3.7-flash-2026-07-15`，耗时约 22.5 秒。这说明此次分诊请求实际调用并收到了 LLM 响应。

## 验证范围

已验证真实 HTTP 请求、前端生产构建和运行日志。当前本机浏览器控制组件版本不匹配，无法自动读取用户现有标签页的本地存储或逐项点击页面；因此浏览器内旧 Token 的具体值没有被读取，根因判断基于代码和新旧 Token 的可重复接口结果。
