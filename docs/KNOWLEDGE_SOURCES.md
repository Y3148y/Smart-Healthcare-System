# 知识源清单与使用边界

> **本文读者**：任何想给本项目补知识内容的人（人或 AI）。
> **性质**：本项目全部临床内容**未经临床审核**，没有任何一条经过执业医师签署。
> **机器可读版本**：[`tools/knowledge-sync/sources.json`](../tools/knowledge-sync/sources.json)（权威登记处，含每条 URL、抓取方式、复核周期）。本文只讲策略与覆盖映射，避免两份清单各改一半。
> **打印当前清单**：`cd tools/knowledge-sync && npm run sources`

---

## 1. 收录标准

`docs/RAG_KNOWLEDGE_CATALOG_2026-09-26.md:41-42` 已经定了规矩，这里只是把它执行到位：

1. **只使用官方机构或公立医院发布的公开资料。** 不采用营销软文、论坛问答、商业健康站。
2. **不复制整篇网页。** 与导诊直接相关的信息改写为本项目自己的短段落，保留原始 URL。
3. **危险信号优先于科室推荐。** 语料先回答「什么时候必须线下就医」，再回答「挂什么科」。
4. **每条内容必须写明出处，并标注「未经临床审核」。** 中文表述与英文原文之间的映射偏差必须留痕。

## 2. 整类不收

| 类别 | 例子 | 原因 |
| --- | --- | --- |
| 商业问答与内容农场 | 各类「在线问诊」站点的疾病页 | `RAG_KNOWLEDGE_CATALOG:41` 明确排除；且无法追溯编写者与更新日期 |
| 征求意见稿 | 各省市互联网诊疗监管实施办法征求意见稿 | 无现行效力。写进文档容易造成「已有监管依据」的错觉 |
| 地方性文件 | 省市级互联网医院管理办法 | 同上。地方规则不能当全国依据；确需引用时必须写明辖区与生效期 |
| 新闻评论 | 媒体报道、专家访谈转载 | 是二手转述，不是发布方原文 |
| 需登录/付费/绕过 WAF 的内容 | 部分期刊共识 | 无法稳定复核，也无法留痕 |

> 曾经考虑保留「上海市互联网医院管理办法」这类地方文件作为业务规则参考，**已决定剔除**。理由：一旦写入文档，读者会默认它是本项目应遵守的规则，而实际上它只对上海有效。

> **待核项**：代码注释引用的「国卫办医发〔2022〕2号 第二十一条」条号未证实（北京市对应条款为第十四条、上海市为第二十九条）。必须人工打开原文核对条号后再引用，不得默认它正确。

## 6. 为什么监管条款不进 RAG

把它们做成语料，患者会在预问诊里读到「不得对首诊患者开展互联网诊疗」。这句话本身没错，但它出现在一个演示系统的对话里，既可能被理解成「这个系统可以做首诊」，也可能被截取成合规话术。合规知识属于**文档层**，不属于**患者对话层**。
