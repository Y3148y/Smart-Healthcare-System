# P0 实施及验收记录（2026-09-29）

## 产品定位与结论

本项目目前是**可运行的辅助预问诊原型，不是可直接对接医院上线的医疗产品**。没有合作医院、真实号源、临床审核和患者隐私合规体系；患者端预约与人工复核均为本机演示流程。P0 的目标是让高风险症状优先被可审计的安全规则拦截，使普通回答可追溯到检索证据、工具执行和调用记录，同时明确失败降级。

## 已实施

| 边界 | 现状 |
| --- | --- |
| 危急预警 | 分诊前运行版本化规则，输出规则编号、命中词、风险级别及行动建议。胸痛、呼吸困难、意识/神经异常、严重出血、气道问题、严重创伤、自伤/中毒、孕产急症等进入紧急流程；常规医生推荐和普通预约停止。骨折、持续高热和剧烈疼痛进入尽快就医提示。否认词与既往症状做局部处理，避免明显误报，同时对胸痛保持保守拦截。 |
| 对话和分诊 | 多轮症状与每次分诊版本持久化。结构化分诊由服务端决定；LLM 仅生成文字解释，不得覆写风险结论。多个科室可分别列为候选。 |
| RAG | 内置来源明确的医学资料按段切片、保留出处，按医学术语和字符向量相似度检索并设可配置阈值；无命中时拒绝生成无依据的医学解释。新上传 TXT/Markdown 为 `PENDING_REVIEW`，管理员明确批准后才进入患者检索并尝试增量更新 Qdrant。适配器有模拟 HTTP 契约测试，当前本机未配置真实向量服务或向量模型。 |
| 模型约束 | 对患者文本及检索文本标记为不可信输入，限制长度、温度和回答长度；对部分诊断/处方表达进行输出拦截，异常时回退为症状相关的保守文案。后台标明 `LIVE`、`DEMO`、`FALLBACK`、`EVIDENCE_BLOCKED` 等状态。此举**不能证明逐条事实均由证据支持**。 |
| 工具/MCP | Agent 与管理员工具试运行均调用同一个真实执行器，记录成功/失败、耗时与结果摘要。`POST /mcp` 提供受管理员认证的 `tools/list`、`tools/call` JSON-RPC 子集。Agent 当前在同一进程调用执行器，**没有独立 MCP 服务及外部 MCP 客户端**。 |
| 人工复核 | 患者可为会话提交一次人工导诊申请；管理员可查看、接单或关闭。它只是持久化队列，**不等同于医疗人员实时接诊**。 |
| 预约 | 紧急或证据不足的分诊无法通过该会话创建普通预约；非紧急分诊仅可选择最新结果中的候选医生，重复请求按幂等键处理。号源为模拟数据。 |
| 观测/部署 | 工具与 Agent 调用日志落库，不再填充虚构耗时或成功率。默认仅监听本机；公开地址禁止启用演示认证；JWT 密钥来自环境变量或每次启动随机生成。 |

## 验证记录

- JDK 17 / Maven：后端 `mvn test` 通过，包含安全规则矩阵、否认与时间语义、会话版本、角色隔离、危险症状预约拦截、人工复核、MCP 工具调用及 Qdrant 模拟 HTTP 契约。
- Vue / TypeScript：`npm run build` 通过；管理页知识检索按钮已实际调用后台并显示命中片段与来源。
- 本机真实 HTTP 冒烟：患者与管理员登录、普通症状二轮分诊、知识依据、胸痛紧急拦截、紧急预约返回 409、人工复核入队、管理员查看、MCP 医生工具查询及调用日志写入均通过。该测试使用演示模型及 H2，不代表真实 LLM、Qdrant 或 HIS 联调。
- 当前进程没有加载 `AI_API_KEY`、`AI_MODEL` 或 `AI_EMBEDDING_MODEL`；不得将演示回答标为真实大模型回答。以前向对话提供的密钥没有写入仓库。

## 上线前阻断项（不能因为 P0 代码通过而跳过）

1. 与医院确定接入主体、服务范围、真实号源/HIS 边界、医疗人员值守与紧急转接流程；现有人工复核队列没有时效保证。
2. 由临床、急诊和法务团队审核预警规则、适用人群、就医提示和误报/漏报；完成真实案例集、压力测试、监测与回滚方案。现有规则仅覆盖成年人本人、非孕产期的普通演示范围；虽识别一些孕产危险词，但**不能据此宣称孕产分诊已获验证**。
3. 实现正式身份认证、同意管理、患者数据加密、访问审计、保留与删除策略；演示密码逻辑绝不能对外使用。
4. 对选定的 LLM、Embedding 和 Qdrant 进行端到端实测及临床安全评估；加上逐条证据支持校验、来源版本和失效管理。当前模型输出过滤及检索阈值无法消除幻觉。
5. 对 MCP 协议进行完整互操作/安全验证；独立医院工具服务、网关认证、超时、熔断及幂等需在真实系统接入时设计。目前 `/mcp` 仅是工具协议子集。
6. 医学知识虽有管理员批准入口，但没有临床审核工作流、来源真实性核验、恶意文件扫描和持久化资料库；待审核与批准资料仅在本机内存中，重启不保留，不应当作正式知识管理系统。

因此，本阶段可用于需求验证和受控演示，**不应对公众提供医疗分诊或真实预约服务**。
